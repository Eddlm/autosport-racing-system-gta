# AUDIT 207 — race cycle: start, development, finish, abandon, hot re-start

**Surface**: `StartRace` / `SetupRace` / `StartCountdown` / `InstanceTrack` / `InstanceGrid`, the finish-and-grace-timer block in `OnTick`, the three teardowns (`CleanRacers`, `CleanEverything`, `OnAbort`), the per-racer `Delete` / `Initialize`, the menu rows that enter or leave a race, the player's own racer, and the grid build up to the 100-car option.
**Date**: 2026-10-25.
**Build audited**: **1092**. `build/build-number.txt` = `1092`; `bin/Release/ARS.dll` and the live `Scripts\AutosportRacingSystem\ARS.dll` are one file, sha256 `8e3ab22dc3b3ff8a1dda4dfd3cd8a7f5c8017f36206032ffa3210dea6c983285`. Source `HEAD e851a09`, `src/` clean.
**Method**: read-only. No build, deploy, commit or game run. The one non-source witness is the live log, `D:\SteamLibrary\steamapps\common\Grand Theft Auto V\Scripts\AutosportRacingSystem\Log.log`, still being appended while this was written: 22:47:15 → 23:20:27 (33 min), 1550 lines, **173 `Error` lines and every one of them the same exception**. **VERIFIED** = the mechanism was read and every writer of the value enumerated here, or reproduced in that log. **PROBABLE** = one step rests on SHVDN or engine behaviour that was not observed.
**Verdict**: **the entity teardown is clean** — no racer, car, ped or blip outlives a race that goes through `CleanEverything`. What does not hold is the state: the field and the phase are statics while the clock and the batch cursor are instance fields, and the paths that reset them are not the same paths, so a re-started race inherits the previous race's deadline and a reloaded script resumes a race it cannot time out. **Two blockers**, both of them a race that ends itself for a reason the player cannot see; and the 100-car option is offered without the four things that fail at that size.

## The loop as the code actually runs it

Every entry point, what it clears, and what it leaves. The rows above sit on this shape.

| Entry (menu row) | Code path | Clears | Leaves behind |
|---|---|---|---|
| **Start Race** (`:891`) | `StartRace` → (`InstanceTrack` → `CleanRacers` + `LoadTrack`) → (`InstanceGrid` → `CleanRacers` + `LoadGrid` + `PlaceCars`) → `AddPlayerToGrid` → `SetupRace` | racers + blips, track props, `LeaderboardFinish`, grid/track flags, `MissionFlag` | `_raceTimedFinishMs` (**B1**), `ParkedDNFs`, `HelpMessages`, `PlayerParticipating`; a silent spectator race when the player is on foot (`:2527-2531` is the only message and it fires only when the roster is empty) |
| **Restart Race** (`:900`) | `_raceTimedFinishMs = 0` → `SetupRace(true, true)`; falls back to the full start when `PlayerParticipating` is false (`:904`) | lap state (`Initialize`), `LeaderboardFinish`, the timer | `ParkedDNFs`, `HelpMessages` (**F2**); throws at `:2627` when the roster is empty and `PlayerParticipating` still says otherwise (**R5**) |
| **End Race** (`:921`) | `CleanEverything` | racers, props, flare effects, no-collision *intent*, leaderboard, DNF counter, timer, route nodes, flags | `TrackPoints`/`Corners`/`IsPointToPoint` (**F3**); the no-collision pairs (**R6**) |
| **Race completes** (`:2301`) | stragglers classified → reward → `Finished` → `CleanEverything` | as End Race | as End Race; the classification never renders (**R3**), `Finished` never observable (**F1**) |
| **Script reload** (`Aborted`) | `OnAbort` | camera, screen effects, freecam prop, props, racers, scaleforms | `RaceStatus`, `LeaderboardFinish`, `PlayerParticipating`, `ParkedDNFs`, `HelpMessages`, `RouteNodes`, `Game.MissionFlag` — and the race resumes (**B2**) |
| **Player leaves / dies / changes car** | *nothing* | — | racer frozen on the car they left, no DNF, no respawn, race waits on the grace timer (**R1**) |

Two structural notes the table makes obvious:

- **The finish test is outside every phase gate** (`:2301-2302`), and the per-racer work above it is gated only on `Racers.Count > 0` (`:2231`, `:2261`). That is what lets B1 kill a race that has not started and what makes the player's absence (R1) invisible: the loop's clock is the field's, not the race's.
- **There is no join path.** `Start Race` is a full re-instance, so a player who wants to rejoin a running field restarts everything; `Build Grid` would be the row that adds a car, and it is removed from the menu at load (`:1394-1398`) with its toggle forced off at load (`:3625`) — the two staged rows are not reachable in a shipped install.

## What survives a hot change

The split that B1, B2 and F2 all sit on. It is not a table of leaks; it is two owners for one race.

| State | Kind | Written by | Cleared by |
|---|---|---|---|
| `Racers`, `LeaderboardFinish`, `RaceStatus`, `PlayerParticipating`, `ParkedDNFs`, `HelpMessages` | **static** | `CleanRacers`, `AddPlayerToGrid`, `SetupRace`, the finish block | `CleanRacers` / `CleanEverything` — **not** `OnAbort` |
| `RouteNodes`, `NodeHalfWidths`, `TrackPoints`, `Corners`, `Bumps`, `Crests`, `IsPointToPoint`, `GridPositions` | **static** | `LoadTrack`, `ClearRouteInfo` | `LoadTrack` for the route, `CleanEverything` for four of the six — not `OnAbort` |
| `_raceTimedFinishMs`, `_nextInLine`, `_gameTimeNextInLine`, `_posUpdateTickMs`, `_longTickMs`, `_countdown`, `_countdownTickMs`, `_trackInstanced`, `_gridInstanced`, `_lastKnownPlayerPace` | **instance** | the finish block, the batch, the countdown, the phases | the constructor — that is, a reload resets them and nothing else does |

The consequence is B2: after a reload the *field* says "a race is running" and the *clock* says "no race was ever timed", so the one path that ends a race without a winner has been silently removed.

## Not verifiable read-only

- **No game run.** B1, R3, R4, R5 and R6 are read from the code; B2 and R7 have the live log behind them. Nothing here was driven.
- **No build.** Build 1092's identity is the sidecar, the build number and the hash equality of the deployed dll with `bin/Release`; none of it was re-derived by compiling.
- **The log's own start path cannot be reconstructed from the file.** It is truncated by the constructor, so the session's `Starting race` line is gone by construction; B2's reading is the absence of a *spawn* line, not the absence of a start line, and it is stronger for that reason. Which of `Aborted`-not-firing and `OnAbort`-throwing is the real one is not decidable from this tree.
- **The engine's treatment of a no-collision partner that was deleted** (R6) and **the exact freeze length of a 100-car build** (R4) are engine-side and unmeasured.
- Whether the player *should* be DNF'd for leaving, and whether a race should end on a results screen, are intent questions, not defects — they are in "owed by the owner".

## Owed by the owner

**Decisions (no wheel time)**

1. **B1's fix direction.** The smallest honest change is to reset the deadline where the race is created — one line in `SetupRace` — so that *every* path into a race starts with no clock. The alternative, gating the completion test on `RaceIsRunning`, fixes the symptom for the new race and leaves the stale value to bite whichever path reads it next.
2. **B2: does a reload end the race, or resume it?** Resuming is the better promise for this install (the reload key is the iteration loop), but it needs the two halves to be reset together: a reload that ends the race must run the full teardown, and one that resumes it must keep the clock. Right now it does neither.
3. **R3: is a result screen wanted?** The classification is already computed; keeping `Racers` and `LeaderboardFinish` alive until the player dismisses them is the cheap version. Retiring the classification is the other answer, and then the reward line should say so.
4. **R4: the ceiling.** If 100 cars is a supported option, the board needs paging, the build needs to be incremental, and the spawn index needs to wrap; if it is not, the list should stop where the code can actually deliver (the `GridSlotsAvailable` clamp is measured against the wrong quantity and never binds).

**Drives (one batch, two races)**

1. B1: run to the first finisher, then Start Race before the countdown expires. One race, one menu sequence.
2. R1: race, get out, jack another car, watch the board. One race.
3. R4: set 100 on Horsetrack and count the field; then set 40 and read the board's last visible row.

**Blockers**

1. **B1** — a re-started race inherits and dies on the previous race's grace timer.
2. **B2** — a reload mid-race resumes a race whose clock has been reset, and it can no longer be timed out.

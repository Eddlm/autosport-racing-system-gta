- **Severity**: **blocker** = can cost a race or crash; **release-note** = a decision or a line needed before the tag; **file** = hardening, the next reader's problem.

**Verdict: no blocker in this scope.** The storage layer is better than its reputation: one store per file, one lazy `ScriptSettings` per store, one write path (`Set` → `Save` → `WriteAtomic`), every key the menu writes is declared, and prune and repair agree on what "unusable" means. What is left is the seam between the three writers — the schema default, the reader's fallback and the value handed to the menu row — and the two passes that run at the wrong end of the load.

## Checked and clean (so it is not re-reported next round)

- **Defaults agree everywhere.** For all 36 `Menu-Settings.ini` keys, the 8 `Menu-Race.ini` keys and the 3 `Menu-Development.ini` keys, the `KeySpec` default, the static's field initializer and the load-time reader fallback were compared one by one; they agree, including the two unit conversions (`HillGripEffect` 100 ↔ `1f`, `OverspeedCutPerTenthG` 0.2 ↔ `"0.2"`). The one exception is cosmetic: `RubberbandingPct` initialises to `0` (`:170`) while the schema and both readers say `100` — it is never read before 3429, so it is a latent second default, not a live bug.
- **No undeclared write.** Every `Set` in the tree was enumerated and diffed against the schema: `Track, Laps, GridSize, PaceMode, PaceOffset, PaceTarget, PaceDeviation, ReverseRoute, AIRacerAutofix, SteerTrace, SlipFromMemory, MenuKey, MenuModifierKey` plus the `SaveRacerSetting` targets and the dynamic `option.ToString()` toggles — all declared. `MenuSettings.Set` refuses undeclared keys with a forced `Error` log (`MenuSettings.cs:30-32`, `SettingsRepair.cs:302-306`), so shape 6's "silently does nothing" does not occur here.
- **Prune and repair agree on "unusable".** `HasUnusableValue` (`SettingsRepair.cs:56-61`) returns true only for a numeric key with no default (`PaceTarget` is the only one), which is exactly the case `Repair` cannot fix (`Default == null`), so a dropped line is never one the repair would have restored, and a kept line is always one `Repair` can fix. The two passes are consistent; only `Save()` contradicts the prune (finding 5).
- **The prune cannot outrace a stale cache.** `PruneOwnedFiles` (3357) runs before the four `MenuSettings` are constructed (3359–3362), each of which loads its own `ScriptSettings` lazily afterwards, so nothing rewrites pruned content from memory.
- **Every legacy read precedes the delete.** `DeleteLegacyFiles` (3460) removes `Settings.ini`, `Options.ini`, `DevSettings.ini`, `DevConfig.ini`, `MemoryOffsets.ini`, `Menu-Racers.ini`, `Menu-DevSettings.ini`; the reads from all of them (`3347–3355`, `3371–3376`, `3377–3392`, `3443–3447`) are all above it in the same method. The `DevSettings.ini → DevConfig.ini` rename at `SettingsRepair.cs:186-192` also happens before the read at 3443.
- **Migrations that can run do run.** `TcsSlipLimitPct`/`TcsTaperSpanPct` (3364–3365), `OverspeedCut` (3367), `PaceMode` (3434), `Hotkeys`/`LogLevel` (3444–3445), `BrakeLearning` (3404) and the `Menu-Racers.ini` sweep (3372–3373) all precede the first read of their key, so `Migrate` finds them absent and writes. Only `MaxCrestLift` (finding 3) is pre-seeded.
- **Enum rows map index → value correctly.** `AutofixMode` (Off, AutoRepair, Invincible), `RubberbandMode` (Natural, Artificial), `PaceMode`, `GridSort` (Power … Random) and `TipFrequency` (High, Medium, Low) are contiguous from 0, so `(Enum)args.Index` and `EnumLabels<T>().IndexOf(EnumLabel(x))` cannot drift; `EnumLabel`'s `Descendent → Descending` substitution is applied on both the paint and the parse side.
- **`Racer.cs` has no menu write sites.** Zero `ItemChanged` / `CheckboxChanged` / `NativeListItem` / `SaveRacerSetting` hits; the file touches settings only through the two `Laps` reads in finding 9.

# AUDIT 03 — the four speed governors

**Surface**: how the corner plan, the route curvature, the terrain factors and the pedal law compose — `ComputeTargetSpeed` (`Racer.cs:2431`), `ApexBrakingSpeed` (`:4359`), `RouteRadiusSampled` (`:4029`), `CrestGripSpeedFactor` (`:2590`), `GetFollowPointSlopeAngle` (`:2636`), `ConvertSpeedToPedals` / `ComputeCombinedInput` / `SplitCombinedInput` (`:2093`, `:2165`, `:2171`), the brake cap composition (`ComposeBrakeCap`, `:2889`) and the brake learner (`UpdateBrakeLearning`, `:2261`).
**Date**: 2026-10-25.
**Build audited**: **958**. `build/build-number.txt` = `958`; `bin\Release\ARS.dll` and the live `…\Grand Theft Auto V\Scripts\AutosportRacingSystem\ARS.dll` are one file, sha256 `12fb8b8ff31667a6…`, mtime `13:21:57`. Source `HEAD 9bdb9af`. The live `Settings\Menu-Settings.ini` has `BrakeLearning = True` and `Menu-Development.ini` has `BrakeLearningNotify = True`, so both halves of the learner are live on this install. The log used for evidence is the session that ran on this binary, `Log.log` 13:21–13:29, on `Tracks\testing\Oct1.xml` (route densified 2350 → 2405 nodes).
**Method**: read-only. No build, deploy, commit or game run. Every number below is recomputed from the constants as they are written in the source (a one-line `python -c`, not the project's own maths), and the live log is used as evidence wherever it happens to carry the case.
**Verdict**: the four terms do compose without a double application — the slope and the crest are each applied once, to the route term alone, and each is dimensionally correct. The defects are in the **gates around** the composition and in the learner. **Blocker 1**: the curvature brake cap, which `AGENTS/AGENTS-WIP.md:128` records as the fix that closed the LSIA hard brake, is inert on every racing lap after the first — a predicate that tests "a plan exists" where its own comment says "inside its braking distance". **Blocker 2**: the brake learner's entrance cut is uncapped per event, so one hot entry — including one caused by traffic rather than by the plan — halves a corner's assumed braking decel for the rest of the race, and the recovery is 14 clean laps.

## How the four actually compose, on this build

The audit brief (and `AGENTS/AGENTS-WIP.md:146`) describes the order as `min(corner, route)` followed by the slope and crest multiplying. **That is not the code.** On this build the terrain factors multiply the route term only, before the `min`; the corner plan takes neither:

```
Speed = min(cornerTerm, routeTerm)                                   Racer.cs:2550
  cornerTerm = cornerSpd + MphToMps(CornerOffsetMph)                 :2548
    cornerSpd = min over NextApexNode..NextApexNode3 that carry
                RequiresBraking of  max(2, ApexBrakingSpeed(apex, vApex))
                ApexBrakingSpeed = sqrt(vApex² + 2·decel·d)          :4386
                  decel = min(BrakingAbility·4, grip)·g·factor
                          + g·sin(mean grade over the span)          :4395-4398
    cornerSpd += corner lift, after the target is achieved            :2477-2486
                 (10 mph/s, 5 mph grace; reset on a new apex)
    cornerSpd += 10 mph while Brain.Corner.Point.IsChicane            :2541-2546
  routeTerm = followTrackSpd + MphToMps(RouteOffsetMph)              :2549
    followTrackSpd = sqrt(grip·g·r) · sqrt(hillGrip) · crestFactor    :2463, :2502, :2516
      r = four-point 2D Kasa fit, 999 for a straight OR a failed solve :4029-4081
  then: ChillOut standoff takes a min                                 :2556-2567
  then: rubber-band factor multiplies (leaders only)                  :2571-2575

pedal: err = Speed − SpeedVectorLocal.Y                              :2102
       input = clamp(err / 3) on throttle, clamp(err / 6) on brake   :2165-2169
       brake capped by ABS · countersteer · route(0.2)                :2889-2905
```

What is **not** in the chain, and matters below: no distance or deceleration term in the pedal law, no rate limit on any target, and no memory of what the target was last tick. The only smoothing in the whole path is the pedal slew (`PedalSlewRate = 6f`, full range in 167 ms, `:2096`).

## What was checked and is clean

Recorded so a later session does not re-open them:

- **No factor is applied twice.** The slope enters as `sqrt(hillGripFactor)` and `HillGripFactorFromPitchAngle` returns a **grip** factor (`AutosportRacingSystem.cs:2975-2983`), so the square root is the speed conversion and is applied once (`Racer.cs:2502`).
- **The crest factor is exact, not approximate.** `sqrt(MaxCrestLift / |ΔGs|)` applied to speed makes the new ΔG exactly `MaxCrestLift`, because ΔG ∝ v² (`:2612-2613`).
- **Both terrain factors are ≤ 1** by construction (`:2981`, `:2612`), so neither can raise a target; and both are applied *before* the offsets (`:2548-2549`), so an offset is not scaled by terrain.
- **The grade in the braking solve is the honest quantity.** `BrakingDecel` integrates `g·sin(mean pitch)` over the same span the ramp uses, in the direction of travel (uphill brakes later, downhill earlier), and it is a separate term from the route's slope factor — different questions, no double count (`:4395-4425`).
- **The radius clamp and the 5 m floor** (`:4431`) keep `RouteIdealSpeedForRadius` finite; a radius of 5 m is 7 m/s, so no divide-by-zero and no zero target.
- **The fit's determinant guard is not the real guard.** `|det| < 1e-6` (`TrackLoader.cs:1123`) is an absolute threshold on a quantity with units of length⁴, so it cannot fire on real geometry; the sagitta test (`:4065`) is what prevents the algebraic fit's "RMS size of the sampling window" failure, exactly as `AGENTS/AGENTS-WIP.md:151` describes. The two are not redundant, but only one of them works — do not delete the sagitta test believing the determinant covers it.
- **The sagitta test is dimensionally sound**: `Sagitta` returns metres and is compared against `0.002 · chord`, also metres (`:4087-4093`), and at 1/3 and 2/3 of the chord it under-reads a circular arc by 11 %, which errs toward "straight" — the safe side for a guard whose failure mode is a phantom radius.
- **`Math.Max(2, ApexBrakingSpeed(...))` and the `cornerSpd <= 5` fallback** (`:2455`, `:2467`) can only raise a degenerate plan, and `ARS.CornerApexSpeed`'s floor is `AiConstants.MinSpeed` 15 mph — no path to a zero target.

# AUDIT 209 — track data and the creator

**Surface**: everything that enters the mod through a file or through the track creator — `TrackRepository` (discovery, parse, start line), `TrackLoader` (`LoadTrack`, the width slew, `DensifyRoute`, `RefreshRouteTopology`, `GenerateRouteInfo`, `BuildApexTable` and the region walk, `BuildGridSlots`), the creator's `HandleTrackCreator` / `GenerateBezier` (`AutosportRacingSystem.TrackCreator.cs`) and its writer `SaveRoute` (`AutosportRacingSystem.TrackFile.cs`), plus the two runtime consumers of a span: `Racer.IsWithinCorner` and `Racer.UpdateCornerRequirements`.
**Date**: 2026-10-25.
**Build audited**: **1092**. `build/build-number.txt` = `1092`; `bin/Release/ARS.dll` and the live `Scripts\AutosportRacingSystem\ARS.dll` are one file, sha256 `8e3ab22dc3b3ff8a1dda4dfd3cd8a7f5c8017f36206032ffa3210dea6c983285`. Source `HEAD e851a09`, `src/` clean.
**Method**: read-only — no edit, build, deploy, commit or game run. Two instruments: (a) the source, read whole along the load path; (b) a Python replica of the loader and the apex detector, in `C:\Users\Usuario\AppData\Local\hermes\cache\scratch\track_probe.py`, run over the eighteen shipped tracks in `Dist\AutosportRacingSystem\Tracks\`. The replica is **calibrated against the engine**: on `F8.xml` it reproduces the ten regions and seven corners the build-958 log printed in `07-track-data.md` — apexes 235/429/742/1170/1881/1954/2151, the same `nodesToDouble` (22, 24, 9, 6, 23, 28, 10), the same blur cull at 602 (`nodesToDouble=167`), the same radius-gate drop at 2073 — with radii within 0.2 m and indices within 1 node. It also reproduces that audit's width table node for node (`Oct1` 103 nodes / 6.75 m, `LSIA` 69 / 6.75). **VERIFIED** = read in the code and every writer enumerated, or reproduced by that replica or by a log line. **PROBABLE** = one step rests on engine/SHVDN behaviour not observed here.
**Verdict**: the **load** path is now honest about its input — the "one stray file stops ARS from starting" blocker of audit 07 is fixed, and densify, the geometry pass and the curvature estimator measure what they claim. What is not honest is the **round trip**: the creator can still save a route the loader throws on (B1), and the apex detector still corrupts the one corner every circuit has at the seam (B2) — on a shipped track, where it silently kills that track's nitrous and moves its first braking plan past its own apex. The writes are not atomic anywhere the mod writes a file, and a crash mid-save now costs a track quietly instead of loudly.

## The seam, and what the apex table does at node 0

`BuildApexTable` rotates a circuit's scan to start on the first node whose smoothed radius clears the 200 m ceiling (`:371-382`) so a region crossing node 0 is walked whole. That works — and it moves that region to the **end** of the scan list, which is precisely where the width rule at `:869` reads a negative node distance and walks the entrance to position 0. Replica output for the one shipped track it affects:

```
El Burro Rally  dense=1701  scanStart=37  p2p=False
  region 0        apex=0   apexPosition=1664  region positions 1659-1700
                  widthNodes=12  width walk=1661  startPosition=0
                  StartNode=37 (scanStart)  LengthStart=1664
                  EndNode=31               LengthEnd=31
```

`StartNode > EndNode`, so `IsWithinCorner` takes the wrap branch (`Racer.cs:3231-3236`) and answers *true* for every node outside 32-36. The corner is real — a 37-node bend with a 55 m radius at the start line — and the two things it feeds are the nitrous veto and the brake-planning entrance. The other seventeen tracks report `walk <= 10` and no `StartNode` outside their own region.

## The creator round trip

What `SaveRoute` writes (`TrackFile.cs:29-240`): `<Data><Trackside Frozen Flares><Model>prop_wheel_tyre</Model><Frecuency>10</Frecuency></Trackside><Name/><Tags/><Route><Point>X Y Z Wide</Point>…</Route><Objects><Prop>…</Prop></Objects></Data>`, to `Scripts\AutosportRacingSystem\Tracks\<name>.xml`, the name sanitised through `Path.GetInvalidFileNameChars()`, trimmed, defaulted to `New Track`, and given a timestamp suffix if the name already exists (`:38-46`).

What the loader reads back: `X`,`Y`,`Z`,`Wide` per point, `Model`,`X`,`Y`,`Z`,`RotX`,`RotY`,`RotZ`,`IsDynamic`,`TextureVariation` per prop, `Trackside/@Flares`. Everything else is written and ignored (R9).

What cannot be read back:

1. **A 2-5 node route** — legal to save (`TrackCreator.cs:48`), guaranteed to throw on load and leave the screen black (B1).
2. **The width profile** — the creator's `_pathWidth` is an `int` and the file stores an `int`, so the save is lossless; the *load* then ramps every step at 0.25 m per node (R2).
3. **The node indices** — densify inserts up to 4.3 % more nodes on reload, and the creator's `RebuildRouteInfo` never calls it, so the apex table is built on a different route than the one the track races with; every node number in a creator log line names a different node after a reload.
4. **A closed circuit's seam** — `RefreshRouteTopology` takes ≤20 m as a circuit and densify never touches the wrap segment (R3).

Two smaller facts about the save path, both read and neither urgent: the existence check runs before the timestamp is appended, so two collision saves inside the same second compute the same suffixed name and the second overwrites the first (`:42-46`, `:232`); and if `Tracks\` is missing, `XmlDocument.Save` throws inside the menu handler, leaving one `OnTick error` line and no file.

- **Not established**: whether the ambient script-thread culture is anything but en-US on this install (R11), and whether `IsWithinCorner`'s global answer on `El Burro Rally` has a second consumer elsewhere — the grep finds one caller (`Racer.cs:3279`), which is the nitrous veto.

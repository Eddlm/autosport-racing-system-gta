# AUDIT 205 — the power channel: burn, multipliers and rubberbanding

**Surface**: every writer that can raise or cut a car's drive force — `StartNitrous` / `StopNitrous` / `UpdateNitrous` and the player's fire path (`Racer.cs:3239-3500`), the single per-frame writer (`ApplyPowerMultiplier`, `:3975-4012`, called from `:3616-3617`), the counter above it (`UpdatePowerCompensation`, `:3949-3973`), the packing law and its two application sites (`ComputeRubberBandFactor` `:2798-2808`, plan trim `:2745-2756`, torque boost `:3987-3991`), the three settings that size it (`AiNitroPct`, `NitrousPowerMultiplier`, `PlayerNitrousPowerMultiplier`) and the engine those values land in (leaked `Transmission.cpp`, `Vehicle.cpp`).

**Date**: 2026-10-25.

**Build audited**: **1092**. `build/build-number.txt` reads `1092`; the deployed `Scripts/AutosportRacingSystem/ARS.dll` and `bin/Release/ARS.dll` are the same file, sha256 `8e3ab22dc3b3ff8a1dda4dfd3cd8a7f5c8017f36206032ffa3210dea6c983285`; source `HEAD e851a09`.

**Method**: read-only. Source and `git log` read; the engine re-read in the leaked tree (`E:/GTA/GTAVSP/GTAV Source/src/dev_ng`); the two raw nitro hashes named against `GTAV-EnhancedNativeTrainer/EnhancedNativeTrainer/inc/natives.h`; `ScriptHookVDotNet2.dll`'s `Hash` and `Control` enums dumped with `ilspycmd`; float arithmetic run in `python`. No build, deploy, commit or game run. The live `Log.log` (build 1092, 23:13) was read but sits at `LogLevel = Error` (`Menu-Settings.ini:27`), so it holds no `Info` diagnostic and cannot speak for this channel.

**Status vocabulary**: **VERIFIED** = read in the code, or reproduced read-only (arithmetic, source read, a named grep). **PROBABLE** = one step rests on something not re-observed today. **UNVERIFIED** is said where it applies. Nothing here is driver-verified.

**Verdict**: **one blocker** (205-01: the burn's state outlives the race on the player's own car), **four release-notes** and **four files**. The brief's three suspicions land differently than expected: the player's bottle is a known, parked item (`player-nitrous-fire`, build 715) whose real cause is now nameable (205-02), and the AI's multiplier has quietly doubled against it since the pair was last measured (205-03). Nothing on this surface crashes, and the two natives the brief asked about are no longer written at all.

## Questions that closed with no defect

- **`SET_ENTITY_MAX_SPEED` / `MODIFY_VEHICLE_TOP_SPEED` — restoration and the car's death.** Neither native is written anywhere in `src/` (grep). History: added in `047b531`, removed in `b8d227c` ("no artificial speed cap for anyone"). So there is no restore path to get wrong — and equally no cap lift for either side: both burn mechanisms are force-only (`Transmission.cpp:1364`, `:1624`), which is why a 5× bottle cannot add top speed. The paragraph at `AGENTS/AGENTS-WIP.md:474-477` that describes the pair is a builds 934-988 log entry, superseded by `:499` three sections later; not a live claim.
- **A burn live when the car dies.** The override is a field on the `CVehicle` (`vehicle.h:2398`), so it dies with the entity, and an AI car deleted by `Racer.Delete()` takes it along. Only the player's car survives teardown — which is exactly 205-01.
- **Who erases the cheat multiplier.** The engine, after every physics step (`Vehicle.cpp:2186-2188`), so the per-frame rewrite at `Racer.cs:4011` is required rather than redundant, and an abandoned AI car returns to stock power by itself.
- **Does rubberbanding touch the player?** No. Both application sites are AI-only: the plan trim lives in `ComputeTargetSpeed`, which the player never runs (`Racer.cs:4780-4791`), and the boost branch is gated on `!ControlledByPlayer` (`:3987`). Natural mode therefore slows AI leaders only, never the player.
- **Can a hand-edited setting produce an absurd state?** No. `AiNitroPct` and `Rubberbanding` carry ladders and the repair snaps any number to the nearest entry (`SettingsRepair.cs:49`, `:70-79`, `:163`, `:171`), so a file holding 1000 becomes 200 (→ 205-06), not 50×.
- **`NitrousEnabled = false` or `Rubberbanding = 0` from the start.** Clean: the fire path is gated at `AutosportRacingSystem.cs:2113` and `Racer.cs:3241`, the card at `:3259`, the boost at `:3987`. The one hole is turning the setting off *mid-burn* — same shape as 205-01, since `UpdateNitrous` returns at `:3241` before it can stop the burn.

## Not verifiable from here

1. **Whether `X` is bound to `INPUT_VEH_TRANSFORM` on this install.** The control map lives inside `update.rpf`; neither the repo nor the leaked code tree carries it. It decides whether 205-02 is "keyboard only, by accident" or "never, on any device".
2. **Whether the AI's 5.0 actually doubles the shove the 2.5 did.** Both bottles are traction-limited off the line, so the commanded ratio need not survive to the wheels. One drive with the `Burn` line at both settings settles it.
3. **How much the rev-limit half of 205-07 is worth** — the flag gate is certain, its effect on a given car's terminal speed is not.

## What to fix first

205-01 is one call: clear the override (`StopNitrous`, guarded on `_nitrousActiveUntil > 0`) from `Racer.Delete()` for the player's car, so teardown cannot leave the vehicle armed. 205-03 is five strings plus one decision — whether `AiNitroPct` is re-based so 100 means parity, or the menu is re-worded to say 50 does.

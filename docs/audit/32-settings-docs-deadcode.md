# AUDIT 32 — settings, menus, docs and dead code

**Surface**: the settings chain value by value (`src/SettingsRepair.cs` schema, `src/MenuSettings.cs` store, the field defaults and `LoadSettings` in `src/AutosportRacingSystem.cs`, every menu row in `InitializeMenu`), the dead and write-only state across `src/`, the durable prose (`AGENTS.md`, `AGENTS/*.md`, `docs/DESIGN.md`, `docs/FEATURES.md`, `tools/PACKAGE-README.txt`), the comments that state an invariant, and the numbers that cannot be reached.
**Date**: 2026-10-27.
**Build audited**: **1277** (`build/build-number.txt`), source `HEAD 85ba39b`. The deployed copy was confirmed identical to the build output — `sha256 b56d79b6…` on both `bin/Release/ARS.dll` and `…\Grand Theft Auto V\Scripts\AutosportRacingSystem\ARS.dll`, both written 2026-10-27 04:20:04. **Read-only**: nothing was edited, built, deployed, committed or driven; the only file written is this one. The live `Settings\Menu-*.ini` in the game folder were read as evidence and are quoted where a row depends on what a real install holds.
**Method**: every row was read in the source at the line quoted. Where a row depends on LemonUI, the library was decompiled rather than assumed — `libs/LemonUI.SHVDN2.dll` 1.5.2, `NativeCheckboxItem`'s two-argument constructor (`: this(title, description, check: false)`) and `NativeListItem<T>.SelectedIndex` (`if (index != value) { … TriggerEvent(…) }`). `docs/check-settings-keys.py` was run: `0 error(s), 0 warning(s) over 47 literal key(s)`, so the code↔schema check is clean and none of what follows is a declared/undeclared mismatch.
**Verdict**: **no blocker.** Nothing here breaks a build or a fresh install. What is left is the *upgrade and hand-edit* surface — which is where this file keeps failing: **two migrations that still cannot run** (the `CrestEffect` → `MaxCrestLift` shim, the `AiNitro` tri-state), **one repair whose result reaches the file and the menu but not the session** (twelve numeric statics read before `CompleteOwnedKeys`, three of which produce a visibly wrong car), and **one Development row that opens in the wrong state**. Around them, a durable doc that describes a brake learner the code deleted twice over, an ABS release law that no longer exists, and a dead-code pile large enough to mislead the next reader about which systems are live.

## What the brief asked, answered directly

**Settings chain, value by value.** All 47 literal keys and the 17 loop-declared debug toggles were checked for the five homes (field default, menu row, save, load, `KeySpec` + domain). The chain is structurally sound: every declared key has a reader, every menu row writes a declared key, every domain the schema declares is the array the menu offers, and `docs/check-settings-keys.py` passes. The three ladders not built through `OptionsFor` agree with it too: grid size and the two hotkey lists are generated from the same arrays the schema derives from, and PI Offset is a hand copy of the same −10…+10 range. The failures are not in the wiring; they are in the **order** (R1, R3, R4) and in the **seeding of one row** (R5).

**A control that saves but opens in the wrong state.** One: Steer Trace (R5). `OpenUpOnThrottleFloorPct` opens in the wrong state only when the file holds an off-ladder value (R4), which the repair then fixes in the file while leaving the row wrong for that session.

**A key with no spec / a spec with no control.** None. `AbsEnabled` is the near miss: its spec default is `"False"` while its row is live and can store `True`, but a Bool spec only repairs unparseable text, so the stored `True` survives — the default is a seed, not a policy.

**A load that runs before the menu is built.** By design, and the source of R3: `LoadSettings` reads the statics, `CompleteOwnedKeys` repairs, `InitializeMenu` seeds from the repaired store. The ten numeric statics without a write-back are the residue.

**A setting stored under two names.** `ReverseRoute` (R6), deliberate and documented, and worth a line because the dead copy is the one a hand-editor would find first (`Menu-Debug.ini` sorts before `Menu-Race.ini`).

**A retired key whose old value now means something else.** None found beyond the documented `PaceMode` reuse (the old single key in `Menu-Settings.ini` migrated into `Menu-Race.ini`, `AutosportRacingSystem.cs:3853`) and the `TcsSlipThreshold` → share-of-peak conversion (`:3775-3776`), both of which are guarded by the "only when the new key is absent" contract.

**Dead and write-only state.** 9 fields (F12), 13 methods (F14), one whole subsystem (F13), two park switches (F15, F16), one unreachable handler (F17). Each row names the line that would read it, or says it has none.

**Doc drift.** F1-F8, F18, F19 — each with the doc line and the code line side by side. The brake learner (F1) and the ABS glide (F2) are the expensive ones: both are durable notes that would send the next session looking for symbols that do not exist.

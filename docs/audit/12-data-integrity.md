# AUDIT 12 — data integrity: what ARS writes to disk

**Surface**: every file ARS writes (`Settings\Menu-*.ini`, `Tracks\*.xml`, `Vehicles\*.txt`, `Log.log`, `pidump.txt`), every value it accepts back from disk, the write/read symmetry of each file, and log growth.
**Date**: 2026-10-25
**Build audited**: **958** — live `Scripts\AutosportRacingSystem\ARS.dll` (2026-10-25 13:21), `build-number.txt` = `958` in both the install and the repo.
**Method**: read-only. No edit, build, deploy, commit or game run. Evidence is the source tree at `9bdb9af`, the live install at `D:\SteamLibrary\steamapps\common\Grand Theft Auto V\Scripts\AutosportRacingSystem` (log session 13:26:23–13:29:28, 273,091 B), and one controlled probe of `File.AppendAllLines` semantics (finding R4).

**Verdict**: **one blocker.** Exactly one write path in ARS is atomic — the settings-repair pass, which runs once at load. Every path that writes *during* a session (a menu key press, a track save, a roster append, a log line) is a truncate-or-append with no temp file, no verification and no backup, and the next load reads whatever survived as truth. The brief's roster model ("BuildPowerCache hashes lines and rewrites the file in place") **does not hold**: the canonical-hash rewrite is in memory only and the file is never touched (`VehicleCatalog.cs:93-95`, `:121`) — the only roster write is an append (`:158`). The real roster hazards are an append onto an unterminated last line (R4) and an unguarded read on the load thread (R3).

## Carried elsewhere — do not re-file

- **A non-atomic track save plus a fatal discovery pass** is **AUDIT 07 T1** (blocker there): `XmlDocument.Save` can leave a truncated file that stops the next boot. This audit adds only F7/F8 to it (the folder is never created, nothing is backed up).
- **The ini truncate-then-write mechanism and the discarded `Save()` result** are **AUDIT 06 S5**; B1 here is its read-back half — what the *next* load does with the wreckage, which S5 does not carry.
- **A stored `Track` that no longer resolves** is **AUDIT 06 S6** (silent substitution, never written back). F11 cites it rather than restating it.
- **`Log` throwing from inside the catch** is **AUDIT 08 L2**; F9/F10 are the growth and concurrency halves.
- **The five write-only track schema elements** are **AUDIT 07 T11**.

## Not a defect — recorded so a later pass does not "fix" it

- The roster file is **never rewritten**; hand-edited names survive forever, which is the documented intent (`VehicleCatalog.cs:133`). Canonicalisation is a load-time in-memory step.
- `Laps` cannot be 1 (its ladder starts at 2) and `Laps`/`GridSize` are snapped rather than clamped — a product choice expressed in the schema, not a bounds bug.
- `pidump.txt` being unreadable by the mod is deliberate: it is a TSV for `Import-Csv`.
- `Menu-Development.ini` is pruned but never completed — **AUDIT 06 S2**, a settings-symmetry defect, not a data-integrity one.

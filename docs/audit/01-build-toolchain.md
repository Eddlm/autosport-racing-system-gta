# AUDIT 01 — build, toolchain, deploy mirror, SHVDN pair

**Surface**: the build graph in `NewRacingSystem.csproj` (`PostBuildEvent`, `CopyArsDll`, `RefreshDist`, `GenerateBuildNumber`), the two warning families the build emits, the `Dist` mirror as the release's data source, the build counter that rides beside the dll, and the SHVDN pairing / API-dll staging.
**Date**: 2026-10-25.
**Build audited**: **958**. `build/build-number.txt` holds `958` (mtime `13:21:57.165`); `bin\Release\ARS.dll` and the live `Scripts\AutosportRacingSystem\ARS.dll` are one file — sha256 `12fb8b8ff31667a6…`, both mtime `13:21:57.639`. Assembly version `0.9.0.0`. Source `HEAD 9bdb9af`, **31** commits ahead of `origin/master` (`749157c`). A race was running on this binary while the audit was read (`Log.log` 13:26–13:29).
**Method**: read-only. No build, deploy, commit or game run. Two facts were read out of the binaries rather than trusted from a log: the PE machine and `CorFlags` of both references (a struct read, no compile).
**Verdict**: the build graph is sound and the deployed dll is provably the output of that build — **no blocker on this surface**. Both warning families are cosmetic: the three `CS0162` come from deliberate `const bool` switches, and the two `MSB3270` fire on references that are pure IL. The weaknesses are all at the edges — the mirror never purges and never runs in CI, the counter cannot see a reference swap, and the build number a bug report will quote is a sidecar file rather than something baked into the binary.

## What the two warning families are worth, in one paragraph each

`CS0162` is Roslyn telling you it deleted a statement. Nothing is mis-compiled and nothing behaves differently — the IL is exactly what a `true` constant would have produced had the code been written as `if (true)`. The value of the warning is the **inventory**: it is the only compiler-visible marker of a park-by-constant, and it names only the first statement of each dropped region. That is why W2 matters more than W1: one constant silently disables six members and four read sites, and the build reports one line for it.

`MSB3270` compares the project's `PlatformTarget` string with the reference's PE machine field, and knows nothing about `ILONLY`. Both references here are pure IL (CorFlags `0x00000001`), so the mismatch is a label on a file, not a constraint on the code: a PE32+ IL-only image asks for a 64-bit process, and it is loaded into one. The proof is not the field, it is the load — `ScriptHookVDotNet.log` shows both assemblies loaded and ARS bound in the running game (W3).

## Owed by the owner

**Decisions (no wheel time)**

1. **The three `Dist`-only tracks** (D4): ship them from the root, move them under `Dist/…/Tracks/testing/` and add `/PURGE` to the mirror, or drop them from `Dist`. The mirror cannot answer this — only the intent can.
2. **The two parked constants** (W2): keep `ShowPeakStats = false` and `KickCardEnabled = false` for the release, or flip one. Flipping either is a one-line change with no other edit, and flipping the kick revives six members at once.
3. **`MSB3270`** (W3): leave the two warnings, suppress them with the named property, or move the project to `PlatformTarget=x64`. Doing nothing is defensible; the risk is a future reader "fixing" it by adding native bits.
4. **`AGENTS/AGENTS-SHVDN.md:25`** (S1): correct the "live install is the nightly" sentence to name SHVDNE v1.1.0.6 as the host and nightly.188 as the CI compile reference — the doc is the only place a later session learns which pair was certified.

**Drives**: none. Nothing in this audit changes behaviour.

**Blockers**: none on this surface. The release gate itself is AUDIT 10's.

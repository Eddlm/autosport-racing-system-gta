# AUDIT 10 — release readiness

**Surface**: version story, `deploy.yml`, package gate, clean install, README / RELEASE-NOTES claims.
**Date**: 2026-10-25.
**Build audited**: deployed sidecar `build/build-number.txt` = **958**; source `HEAD` = **`9bdb9af`**, **31** commits ahead of `origin/master` (`749157c`).
**Method**: read-only. No build, deploy, commit or game run. Every row carries a file:line, a command's output or a commit hash, and is marked VERIFIED (observed here) or PROBABLE (mechanism read, not observed).
**Verdict**: the *build* is in a good state — CI is green on the last 100 master pushes, the package structure is proven by the shipped v0.8.6 artifact, and nothing in the package depends on a file that exists only on this machine. The *release text* is not ready: two claims in `docs/RELEASE-NOTES.md:15` are false against the code, and the number the release will carry is not 958.

Hunted through every file path the script touches. **Nothing in the shipped package depends on a pre-existing machine file**, and there are three build-time-only dependencies, all of which CI survives (the last 100 workflow runs are all green):

| Dependency | Why it is safe |
|---|---|
| `NewRacingSystem.csproj:56` prefers the live `D:\SteamLibrary\…\ScriptHookVDotNet2.dll` | Falls back to `libs\ScriptHookVDotNet2.dll`, which **is tracked**. CI green proves the fallback compiles. Silent divergence risk: R2. |

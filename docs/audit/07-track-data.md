# AUDIT 07 — track data: schema tolerance, densify, apex table, creator

**Surface**: the track pipeline — `TrackRepository` (file discovery + parse), `TrackLoader` (route read, `DensifyRoute`, `GenerateRouteInfo`, `BuildApexTable`, `AssignCrests`, `AssignBumpNodes`, `BuildGridSlots`), the creator's `RebuildRouteInfo`/`GenerateBezier` (`AutosportRacingSystem.TrackCreator.cs`) and its `SaveRoute` writer (`AutosportRacingSystem.TrackFile.cs`), plus every consumer that reads `TrackHalfWidth`, `Corner.StartNode`/`EndNode` or a node index as a distance.
**Date**: 2026-10-25.
**Build audited**: **958** (`build/build-number.txt` = `958`; source `HEAD 9bdb9af`, 31 commits ahead of `origin/master`). The live `Log.log` on this install was written by this binary today, 13:26-13:29, and its `F8.xml` load block is quoted below.
**Method**: read-only — no edit, build, deploy, commit or game run; the driver's own `Dist/AutosportRacingSystem/Tracks/{F8,TestOct}.xml` and `testing/` were read but not touched. Two instruments: (a) the live `Log.log` from the 958 session, aggregated rather than read line by line; (b) a Python replication of the loader's read/width-slew/densify and of the ±2/±4/±10 curvature windows, kept in `C:\Users\Usuario\AppData\Local\hermes\cache\scratch\` (`track_data_probe.py`, `warp.py`, `calib.py`, `regions.py`) and **not** in the tree. The replica is calibrated: it reproduces the densify count exactly (2350 → 2405, as the live log prints) and every one of the ten `smoothedR` values the log prints, to 0.1 m.
**Verdict**: the load path is honest about *geometry* and dishonest about *input*. Densify, the geometry pass and the curvature estimator are sound and measure what they claim (the replica agrees with the engine at ten apexes); the defects are at the edges — a file the loader cannot read back (T2), a file it accepts and then cannot start on (T1), a span that silently collapses on a seam (T3), and a set of silent coercions where the file says one thing and the loaded route is another (missing node → `NullReferenceException`, garbage number → `0`, width → a ±0.25 m/node ramp, and 1.5 m node steps left in place while every consumer divides by "1 node ≈ 1 m"). **Blockers: 3 (T1, T2, T3), ranked first.**

The route reader is `TrackLoader.cs:110-135`; the prop reader is `:47-101`.

## The creator round trip

What `SaveRoute` writes (`TrackFile.cs:29-240`): `<Data><Trackside Frozen Flares><Model>prop_wheel_tyre</Model><Frecuency>10</Frecuency></Trackside><Name/><Tags/><Route><Point>X Y Z Wide</Point>…</Route><Objects><Prop>Model TextureVariation X Y Z RotX RotY RotZ IsDynamic</Prop>…</Objects></Data>`, saved to `Scripts\AutosportRacingSystem\Tracks\<name>.xml`, name sanitised through `Path.GetInvalidFileNameChars()` and a timestamp suffix on collision.

What the loader reads back: `X`,`Y`,`Z`,`Wide` per point, `Model`,`X`,`Y`,`Z`,`RotX`,`RotY`,`RotZ`,`IsDynamic`,`TextureVariation` per prop, `Trackside/@Flares`. Everything else is written and ignored (T11).

What cannot be read back:
1. **A 2-5 node route** — legal to save (`TrackCreator.cs:48`), guaranteed to throw on load (T2).
2. **The width profile** — the creator's `_pathWidth` is an `int` and the file stores it as an `int`, so the save is lossless; the *load* then ramps every step at 0.25 m per node (T4), so the road that comes back is not the one the creator drew.
3. **The node indices** — densify inserts up to 4.3 % more nodes on reload (T6), so every node number the creator logged names a different node after a reload (T7).
4. **The apex table itself** — built against the un-densified route in the creator and against the densified one on reload (T7).

Two smaller facts about the save path, both verified by reading and neither urgent: the name-collision check happens *before* the timestamp is appended, so two saves landing in the same second with the same name overwrite each other (`TrackFile.cs:42-46`, `:232`); and if `Tracks\` is missing the `XmlDocument.Save` throws `DirectoryNotFoundException` inside the menu handler, leaving only an `OnTick error` line and no file.

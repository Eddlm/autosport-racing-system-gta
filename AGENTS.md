## AI and race behavior
- Ghosting was removed during avoidance cleanup; rebuild it later with the avoidance system.
- Passengerize: AI drivers move to the passenger seat while a rival is within combined half-length + 0.5m, preventing GTA V contact swerves. Restore driver seat when clear; never apply to player.
- Avoidance: independent left (negative) and right (positive) walls snap to nearby rivals, then open at 2 m/s. Car edges respect walls (clamp in `ApplyRivalWalls`); the wall-collapse case (gap < car width + 1m) is an empty TODO — no lift-off yet. Ignore an ahead rival for the lane-pick when heading difference exceeds 20° (`ComputeAvoidAheadLane`).
- Aggression: 0–100, player remains 50; grid assigns first=0 through last=100, rounded to 10 (`StartCountdown`). It scales avoidance buffer (2 m→0.25 m via `Remap(Aggression, 100, 0, 0.25, 2, clamp)` — descending input range keeps the clamp ascending) and allowed TCS wheelspin (1.5→2.5; base 2.0 ±0.5). Leaderboard shows purple `(pressure)`, not aggro.
- Braking uses `v₀ = √(vTarget² + 2·decel·distance)`; `brakingAbility = min(BrakingAbility*4, currentGrip)` and decel is `brakingAbility * gravity * 0.5` (`MaxSpeedForBrakingDistance`). The `+1 m/s` overdrive was removed (1 Aug 2026) — the plan is now strictly kinematic. Take the minimum with route-curvature speed. Since 2 Aug 2026, `vTarget` is the **apex speed** and `distance` is measured to the **apex node** (`c.Node`) rather than the corner entry (`c.Node - c.LengthStart`) — brake-to-apex targeting. Since 7 Aug 2026 the safety margin is `cornerSpeed × BrakingCoastSecondsBeforeApex` (2 s): the car reaches corner speed 2 s before the apex and coasts the rest — margin scales with corner speed (tried fixed 20 m same day, rejected as wrong feel).
- Corner speed scans every corner node for the tightest `PreciseCurveRadius`; precise/general radius windows are ±4/±10 nodes and use full grip.
- Route curvature samples from `RouteWindowStart` (hardcoded 0.5 s since the pressure-driven lookahead was reverted — see Pressure-driven lookahead), speed-based. Hill grip was removed from `ComputeRouteSpeed` (1 Aug 2026); slope loss is now a separate power-law factor applied after the route-speed computation.
- Steering uses one wall-respecting lane bias. Its speed limiter applies only when steer/yaw have the same sign; the limit is `max(kinematic × 0.8, LateralTractionCurve × 0.33)` (`ApplySteerLimits`).
- Corner line phases (simplified 7 Aug 2026): the corner line is split into **two independent lane systems** plus avoidance, resolved in `ComputeSteering`: **System 2 (high-speed line, `ComputeHighSpeedLane`)** always runs and positions the car on the inside edge of the track's own curvature (signed angle over ±20 nodes, 1° deadzone — fully independent of `Brain.Corner`); **System 1 (corner outside approach, `ComputeCornerTargetLane`)** only *temporarily overrides* System 2 with the outside line during the approach window (5 s→1 s before apex, `holdOutsideUntil = 1.0f`), then lets go (`return 0f`) so System 2's inside edge takes over naturally. Avoidance overrides both when active. No lerp phase — hard switch from outside to inside.
- Inside intensity → **corner pursuit gain (7 Aug 2026)**: the inside line no longer lerps between center and edge. `ComputeCornerTargetLane` always targets the inside track edge (`-cornerDir * safeBound`); instead the **lane-bias gain** scales how hard the edge target is pursued: `Remap(curveRadius, 250, 25, 0.01, 0.5, clamp=true)` replaces the old fixed 0.25x corner gain (`ApplySteerLimits`/`ComputeSteering`), so 25 m hairpins commit at 0.5x (as snappy as avoidance) and 250 m corners barely pull (0.01x). **The input range is descending on purpose** so the output clamp stays ascending (min 0.01 < max 0.5). Avoidance keeps its fixed 0.5x gain. The 250 m wide end is deliberate: corners beyond ~500 m radius are effectively straights, so any wider bound would be dead range.
- **Unified `AccelerationCap` (2 Aug 2026)**: single float in `[-1, +1]`. +1 = full throttle, 0 = coast, -1 = full brake. Re-rises at 0.33/s toward +1 each frame (frame-independent via `TickScale`). Each "lift off" source lowers via `Math.Min`; applied once in `ConvertSpeedToPedals`. **Replaces the old `understeerThrottleCap` local and the `_avoidLiftOff` bool** as the unified input cap. **All sources are smooth mappings, never binary.** Currently one source: avoidance (`Remap(rivalDistance, 0, 5, -1, 1, clamp)`, 5m → +1, 0m → -1, lifts or brakes proportionally as a rival closes). The old steer-in understeer-lift source was removed 7 Aug 2026 (the `_steerOver` clamp formula became useless once the corner pursuit gain took over steering aggression). The old projection off-track source moved to the speed domain (see Speed-domain redesign). Sources SET the cap, the rise only fills the gap. "Only replace if lower" — never override an active source.
- **`ProjectAhead()` (2 Aug 2026)**: 1-second kinematic projection on the racer — `pos + v*t + 0.5*a*t²` with t=1, where a is the average of the last ~10 frames' world-frame accelerations from `UpdateTickData`. Returns `Vector3`, world space, 3D. Used in debug visualization (white line + sphere from car in `showAggro`; sphere flips red, track edges drawn green/red) and as the speed-domain projection source (see Speed-domain redesign). No longer feeds `_accelerationCap`.
- Debug: ShowTrack draws only start/apex/end green chevrons + apex radius (R) and speed (SPD) text; ShowInputs draws green/white/red pedal trail + lane debug. ShowAggro and ShowPhysics default off.
- AI nitrous visual/cheat-power prototype exists and is **currently ENABLED** in code (`AiNitrousEnabled = true`) as part of the Maneuver system (Nitrous + Yield). The AGENTS.md note that it "must remain disabled" predates the maneuver system; tune via `AiNitrousEnabled`/`NitrousPowerMultiplier`/`NitrousDurationMs`.
- Pressure (31 Jul 2026, simplified since): per-racer 0–100 state, updated during a race from the nearest racer within 100 m. Target is a proximity ramp — `targetPressure = Aggression · t` with t mapping 100 m→0, 20 m→1 — so it rises 2/s toward target and falls 30/s away from it. The old "crowd deduction / nearby racers" logic was removed; pressure is now pure proximity × aggression. Pressure adds a fixed overspeed: `followTrackSpd += 5 · Pressure/100` (max 5 m/s at Pressure=100).
- Braking overdrive (removed 1 Aug 2026): the old `cornerSpd = MaxSpeedForBrakingDistance + 1f` (+1 m/s overdrive) was stripped. The braking plan is now strictly kinematic.
- Hill grip (1 Aug 2026): the old `HillGripMultiplierFromVelocity` and `HillGripDeltaGs` were removed from `UpdatePerceivedGrip` — `CurrentMechanicalGrip` is now pure `baseGrip × groundMultiplier`, with no hill-based grip modifier baked into the grip value itself. Instead, a new slope power-law loss `loss = 3 · θ²` (θ in radians) is computed at the follow point and applied as a speed factor `√(1 − loss)` to **both** `cornerSpd` and `followTrackSpd` in `ComputeTargetSpeed`, before the pressure overspeed.
- Pressure offset cap (1 Aug 2026): `PressureMaxSpeedOffset = 5f` m/s. `followTrackSpd += 5 · Pressure/100` — a fixed overspeed, purely proportional to pressure (0 at 0, 2.5 m/s at 50, 5 m/s at 100 = 11 mph), always applied (no gate). The radius-delta dependency and the old gate were removed — the offset is just pressure × constant.
- Speed target asymmetry (1 Aug 2026): `cornerSpd` is the "ballpark" speed (kinematic braking plan, slope-grip, +5 m/s flat offset), while `followTrackSpd` is the precise dynamic speed (slope-grip, vertical curvature, pressure overspeed). They're intentionally asymmetric: corner is a loose target the route can lower; route is the tight one the min takes. Do not add a flat offset to followTrackSpd to "balance" them — the asymmetry is by design.

## Blow-through analysis (1 Aug 2026) — cars together blow through corners
- Question: what makes a pack blow a corner? Suspected a speed override/offset from pressure or avoidance.
- **Proven (code):** the corner speed guard releases at the apex for every car. `GetNextCorner(currentNode)` returns the first key corner with `Node > currentNode`, so the instant `currentNode >= apex` the target flips to the next corner. `MaxSpeedForBrakingDistance` then measures to that far entry → `cornerSpd` becomes huge → from apex to the next braking zone, the current corner's speed cap is gone and speed is `min(huge, followTrackSpd)` = pure route curvature + pressure blend. Steering releases with it: `ComputeCornerTargetLane` gates on `timeToApex > 5s` returning to the natural lane (see Corner-approach gate), so once the corner flips, the inside-line hold is dropped immediately. This is pack-independent.
- **Proven pack-specific aggravators (code):** `Pressure` is proximity-driven (`UpdatePressure`), so a duo runs near `Aggression`; the avoidance `AccelerationCap` source only brakes when a rival is directly ahead (side-by-side = no brake at all), and when it does fire it caps to the leader's *live* (already too fast) speed — avoidance propagates speed, it never raises it.
- **Not proven / retracted:** earlier claim that pack shoving → tracker node jumps → premature corner retarget. The tracker (`UpdateTrackPosition`) searches ±6 nodes and only globally rescans when the closest local candidate exceeds `max(TrackHalfWidth + 10, 25)` m; a 25 m+ deviation is not established for side-by-side racing. Do not cite this without in-game telemetry.
- Working theory: blow-through is apex-release of the corner cap (all cars) amplified by pressure raising the follow-track speed (pack duos near max pressure). Not confirmed in-game yet.
- **Avoidance throttle-lift (1 Aug 2026):** when cars are corraled between rivals and the avoidance walls collapse (gap < car width), the `ApplyRivalWalls` collapse branch triggers (empty TODO — see Walls-collapsed avoidance). If there's a rival directly ahead, the unified avoidance source (`Remap(rivalDistance, 0, 5, -1, 1)`) lifts/brakes toward that rival's distance. This is a defensive throttle-lift, not aerodynamic. In a pack corner, if the leader is already going too fast (blow-through), the follower matches that speed rather than braking to a safe corner speed.

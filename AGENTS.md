## SHVDN build compatibility (release-critical)
- **The asi and the API dll are a matched build pair, and no version check can see a mismatch** — both builds' v2 dll reports `ScriptHookVDotNet2 2.11.6.0`, while the bridge (`SHVDN.*`, in the asi's own managed assembly) changes member by member between builds. ARS needs `ScriptHookVDotNet2.dll` **from the same build as its asi**; a foreign one loads, resolves as "API version 2.11.6", then dies at the first bridge call with `MissingMethodException`. **Compile-clean proves nothing**: `src\` builds against the bundle's v2 dll with zero errors and still fails at runtime.
- **`VerifyScriptBridge()` (`353d65f`)** probes `Game.GenerateHash` in the ctor after the log banner, logs the cause (`forced: true`) and rethrows, so a bad install is diagnosable rather than silent. **Order is load-bearing: no native call may precede it, and none may sit in a static field initializer** — that was the dead `RacerModels`, now pruned, and it made the ctor never run, so `Log.log` was never opened.
- **The public download's bundle cannot run on a current game at all** (its bridge fails to initialise — every script dies), so a SHVDN build matching the game version is a prerequisite ARS cannot supply. **Never ship a pinned `ScriptHookVDotNet2.dll` in Dist** (it would manufacture that mismatch); a stray `ScriptHookVDotNet3.dll` is harmless. The v2 API is deprecated by its own dll — the v3 migration is the exit. Matrix, failure signatures and the `Util\shvdn-compat\` lab: `AGENTS-SHVDN.md`.

## The per-frame pipeline (Racer, timed core)
Order, each step consuming the last:
1. `UpdateTrackPosition` — local ±6-node search (global rescan past ~25 m), time-based lookaheads, route radii, lap ticks.
2. `ComputeTargetSpeed` — builds the **intended speed** (Speed pipeline), sets `_cornerSpd` from the current corner.
3. `ComputeSteering` — resolves the lane (Lane systems), derives heading/lane/recovery angles, runs the PD to `Control.SteerDegrees`. **The heading-error term is load-bearing — do not remove or merge it into the lane term.** It anchors the car to the track direction and catches lateral-drift overshoot at lane centre; merging heading + lane into one "aim at the point" angle sails past the lane and oscillates (tried, reverted).
4. `ApplySteerLimits` — speed-based steer clamp on the *allowance*, **exempting countersteer**: the limit exists to stop the car being steered *into* a slide, not to cap the correction that recovers it, so it applies only when steer and yaw share sign (the same test `TranslateSteerToInput` uses for its 360°/s countersteer slew, i.e. the zombie block's original condition, restored 2026-09-13 per `07d5e57`). Also owns the slide-side brake release: past the full-countersteer threshold it drops `MaxBrake` to zero, which lands as the post-slew `Min`, so the brake is released **instantly** rather than ramped — while the **restoration** is ramped, at the `MaxThrottle` recovery rate, so full braking is back ~0.5 s after the slide ends.
5. `ConvertSpeedToPedals` — intended speed → one `[-1,1]` combined input, split to throttle/brake, capped/slewed. **Full countersteer holds the pedal at `CountersteerRollThrottle`** — no brake, a hair of throttle so the tires keep rolling — applied *after* the offshoot cap (so that cap cannot command brake mid-slide) and *before* `ApplyThrottleCap` (so TCS keeps the last word). **Its gate must use forward speed, never velocity magnitude**: reverse reads as a ~180° slide, so a magnitude gate would starve the stuck-recovery reverse. **No reverse routing** (forward/brake only; reverse exists solely in stuck recovery). **GridWait lives in three places** — `ComputeTargetSpeed` (pins `Intention.Speed`), `ProcessAI` (handbrake refresh), `TranslateSteerToInput`/`TryGetSteerContext` (steering skip); keep them in sync.
6. `TranslateSteerToInput` — smooths steer toward target, remaps degrees → -1..1. Traction control, maneuvers and stuck recovery run around these.

## Lane systems — where on the track the car aims
Resolved in `ComputeSteering`, later overrides earlier:
1. **High-speed line (`ComputeHighSpeedLane`)** — always runs; puts the car on the **inside edge of the track's own curvature**, from geometry only (signed angle between the track direction and a speed-scaled lookahead node — the sample distance in metres is the seconds-of-travel constant × speed, an **inline literal inside the method**). Suppressed when that angle falls inside a deadband (wide ≈ straight); the target is binary, not graded — a gentle bend and a hairpin get the same lane, differing only in how early they trip the deadband. Lengthening the lookahead cuts both ways: a longer chord subtends a bigger angle, so it engages earlier **and** releases earlier on exit (the far sample lands on the straight sooner). **Two steering lookaheads, only one of them named — do not conflate them**: this method's chord is anonymous, while `SteerLookaheadMinMeters` floors the *other* reference, `LookAhead.SteerRef` (= `speed / grip` × a **manual grip→lead scale**, applied in `07d5e57` so the grip trend stops driving corner cutting), which feeds the heading error, the steer aim point and the wall stubs. The constant's name reads like a general steering lookahead; it is not this one (see `AGENTS-BACKLOG.md`).
2. **Corner outside approach (`ComputeCornerTargetLane`)** — temporary override; holds the **outside line** during the approach window before a key apex, then releases (`0f`) so the inside line takes over.
3. **Avoidance (`ComputeAvoidAheadLane`)** — overrides both when a rival ahead needs passing.
4. **`ApplyRivalWalls`** — clamps the final lane between track bounds and rival walls. **Invariants: the car's full width always stays on track; the buffer always includes the average of both bounding boxes (no physical contact possible) + an aggression extra.** The overlap window is asymmetric by design: generous from a rival ahead, nearly none from one just passed.

Design rules:
- **Lane systems only *set* the target; how hard it is pursued is uniform**, set by the steering lane conversion (below) — the old per-system gain discipline is gone with the proportional conversion. Revisit only if outside commits feel too aggressive.
- **Corner approach** engages only when the car arrives at the window **already above its own grip-derived speed for that apex** (per car: grip × gravity × radius, downforce included) — the apex says "slow down", the car says "I'm faster than that", so it opens the entry. Let-go time scales with track width — and the window start is *derived* from the same release time, so retuning the width coefficient moves the hold's entry and its release together. The hold decision is made once per approach (keyed to the apex node, reset after it) and can flip to "hold" if the car accelerates into the braking window after a slow entry — it never flips back. Corner *radius* no longer suppresses the hold: an easy corner suppresses itself simply because the car is not above that apex's speed. Three things suppress it outright — close-corner and chicane (both via `SuppressOutsideApproach`) and an **entrance-direction gate**: an entrance heading diverging more than ~60° from the current track direction returns no hold at all. **Watch the coupling with the Route Speed Limit toggle**: with route speed on it holds sweeping corners under the apex speed, so gentle bends suppress their own hold; with route speed off (999) nothing does, so gentle bends take the outside again — if sweepers look wrong in one toggle state and right in the other, that toggle is why.
- **Corner-commit maneuvers** (DiveBomb/DefendLane) replace the outside hold with a lane beside the target rival on the corner's inside — same formula, opposite target frame; both clean up when their apex is passed (defend also on overtake).
- The corner line phases are a **hard switch** (outside → inside), no lerp.

## Gs-aware preview steering (lane error blend)
- Nose-aimed steering measures lane error at the car's position, but at speed centrifugal force (already measured by `ProjectAhead`) curves the real path, so it overshoots. The lane error in `ComputeSteering` therefore blends legacy (at the car) with the **0.5 s Gs-aware projection** (`LookAhead.HalfSec` + `ProjectAhead(0.5f)`, a hardcoded local half-and-half — there is no knob); the **1 s** slice is the off-track cap's read, not this one.
- **Lane pursuit conversion (proportional, `b333dc4`)**: lane error (metres) → steer angle by a **fixed degrees-per-metre gain**, clamped to a ceiling that eases with speed (descending-input Remap). The old `atan2(laneError, lookahead)` is gone: its gain was `1/lookaheadDist` with lookahead = speed/grip, so authority shrank exactly when speed rose or grip fell. A NaN guard sits before the clamp. `LaneGainExponent` is a dead field — declared, never read, and in no ini (it is not a save-compatibility key); removed-curve history in `AGENTS-TECHNOTES.md`.
- **Physical repulsion** (velocity-oriented box, separate from walls): inside it, react only to rivals **actually closing laterally** and **add** a steer-away term to the lane bias — never overwrite the bias (overwriting broke lane pursuit: parallel traffic made the sign filter coin-flip and replaced the bias with ~0). Magnitude scales with closing speed × distance.
- The projection read is one frame stale by design (`RunTimedCore` runs before `ProcessTick` refreshes `AccelerationVector`) — same staleness all projection consumers accept.

## Speed pipeline — how fast the car goes
- **`cornerSpd`** — the "ballpark": kinematic braking plan `√(v²+2·a·d)` toward the **apex speed**, over the distance to the **apex node**. No flat offset of its own. The decel comes from `BrakingDecel`: a grip-limited base **plus the gravity component of the mean grade over the braking span** (car → that apex's braking target, sampled along **the same trimmed span the solve integrates** — passing the raw span instead counts the coast to the apex in the mean), floored positive — downhill loses decel, uphill gains it, and the mean is the exact quantity for this kinematic form (`∫a·ds`, so the per-node profile genuinely does not need preserving). `TrackPoint.Elevation` is `90·sin(pitch)`. The same helper feeds the fallback `MaxSpeedForBrakingDistance`, so the two solves can't drift.
- **`followTrackSpd`** — the "precise": route curvature `√(g·grip·radius)` from a time-based lookahead window (three circumradius sample points). The window is in seconds ahead, not grip-scaled, so it responds consistently at all speeds. Gated by the AI Settings **Route Speed Limit** toggle: off drops it to 999 so the `min(cornerSpd, followTrackSpd)` always takes the corner plan (the slope/crest factors and the steer-limit blend still act on that 999 first, all far above real speeds).
- **Slope grip loss is LIVE** (exponential pitch model applied to corner + route speed); ignore any older note claiming otherwise. Hill/crest grip floors (the slope model's floor plus two vertical grip factors) are tuned as one knob — **read the code for current values**. Known issue: the model reads an upcoming hill and cuts speed before the car reaches it (sudden brakes).
- **`Intention.Speed` = min(cornerSpd, followTrackSpd) + Speed Offset**, then clamped by engine top speed, `MaxSpeed`, and the off-track projection cap. **Speed Offset** (AI Settings → `Menu-Settings.ini`, even mph −10…+10, default 6 — the shipped preference, matched by the code default) is the pipeline's *only* flat fudge and is applied once at the end, so it also lifts apex-limited speed — apex speed itself stays pure physics `√(grip·gravity·radius)`. The old hardcoded +8 here and +6 on the route term were removed; chicane's +10 stays.
- **Pedal gain**: one **linear** map for both pedals, no feedforward — combined input = speed error ÷ `FullPedalSpeedErrorMps`, with the **brake side divided by `BrakeErrorMultiplier` on top** (braking is deliberately the softer side), clamped to ±1; both pedals then ramp to that target at a fixed slew rate. **There is no case for a direction swap** — its error is the sum of the magnitudes, so it saturates on its own. The old Gs-based gain under-braked in long braking zones.
- **Off-track projection cap (`ApplyOffshootBlend`)**: when the 1 s projection lands outside a corner, the max combined input is capped by how far off-centre it lands — full throttle across the inside half, falling from the centre line to zero at the track edge, then a light brake out to the outer limit (endpoints and floor in the code). The side is the *same* reference as the gate: the track angle 1 s *behind* the car decides which half is "inside", and the ramp is signed by it, so the rule does not depend on the gate to be one-sided. Gated by the target lane (no lane → no cap); "outside" is judged from the track angle 1 s *behind* so it stays relevant through the corner. Applied as a `Min` on the combined input, so it never cuts braking — but a negative cap **is** a brake command over the plan's own throttle, and its onset is a ramp only because the pedal slew sits downstream. The reference node comes from `FindNearestTrackPoint(proj, node, behind: 0, ahead: ~1 s of travel)`: **the window must reach the projection** (1 node ≈ 1 m), because the helper's old hidden ±10 window silently measured every moving car against the node 10 m ahead of it (fixed in `f1acebd`). Instant clamp, not a decay.
- **Throttle/brake avoidance override: REMOVED** (the old `_accelerationCap` was scaffolding nothing pulled down). **Asymmetry is by design**: corner is the loose target, route the tight one — do not "balance" them with flat offsets. **High-grip cars don't respond to braking-side tuning**; route-curvature control wins.

## Corner lifecycle (precomputed apex table + four held targets)
1. **Apex table at generation** (`BuildApexTable`, called at the end of `GenerateRouteInfo`): a second pass walks the track **sequentially in chunks** and takes each chunk's smallest precise radius as its apex, kept only under a corner limit. `ARS.Corners` holds node + radius + tentative 1g speed only (older local-minimum criteria over ±1 then ±4 neighbours made every noisy node a corner; the chunked pass fixed it). **Close-corner rule**: within 30 nodes of the previous apex → dropped (they read as one); 30–100 nodes → kept but flagged `SuppressOutsideApproach` (no outside hold, no corner-commit). **No radius flag survives**: gentle bends are no longer written off at generation — the racer decides at the window (see the corner-approach rule below), so the same bend is "easy" for a grippy car at low speed and a real corner for a loose one. `ComputeCornerTargetLane` looks the flag up by apex node (not copied).
2. **Held apex queue per racer** (`UpdateApexLeapfrog` + `RefillApexQueue`): targets persist until passed, then leapfrog and refill; redundant close apexes skipped unless materially slower; the queue invalidates on route-data change or a low-speed incident. Per-car apex speed = `√(grip · gravity · radius)`.
3. **Braking map (`ApexBrakingSpeed`)**: each held apex feeds `v = √(vApex² + 2·a·d)` over the usable distance (apex distance minus a buffer of seconds × corner speed); `cornerSpd = min(map(apex1..4))` — the lowest demand wins. The buffer is a flat `EntranceBrakeBufferSeconds × speed` — pressure does **not** scale it, and the `EntranceBrakeExtraDistance` term beside it is a constant 0. DiveBomb's deeper braking target comes from elsewhere in the plan, not from shrinking this buffer.
4. **Route-speed split**: the near window gauges `followTrackSpd` — the authority for **sweeping corners** — while the four-apex map handles tight corners from far away. Both always run; **min governs** (the old 2 s gate caused unawareness in complex curves). **Handover is positional and unconditional**: route speed takes over the moment the braking target (entrance node) is passed, with no speed condition (an mph-delta handover braked far too late; a margin condition let the corner map brake inside corners). **The apex plan is released only once braking is genuinely done** (entrance passed AND the car at corner speed + a small margin).
5. The old live rolling scan and the far-killer window scan are **superseded**. But `Brain.Corner` is **live again**: `CommitApexQueue` re-instances it each tick from the nearest held apex, so outside-approach, corner-commit and chevron consumers read live state sourced from the queue. New consumers may read either; the queue carries more.

Track facts: **1 node = 1 m**. Circuit lookaheads use modulo; point-to-point clamps.

## Per-racer state
- **Aggression** (0–100): grid-assigned by position (first lowest … last highest); the player stays mid. Scales the avoidance buffer and allowed TCS wheelspin.
- **Pressure** (0–100): proximity × aggression — ramps from the nearest rival inside a radius; rises slowly, falls quickly. Its old `±3 m/s` offset on `followTrackSpd` was removed; pressure still drives divebomb/defend/arming.
- **Stability-aware grip — absent, not neutral**: `AvgGroundStability` **no longer exists** (removed in `c18444a`; zero occurrences in `src`). `CurrentMechanicalGrip` is built as `(BaseMechanicalGrip + DownforceGripBonus) × GroundGripMultiplier` with **no stability factor** (see `UpdatePerceivedGrip`), so the stability dimension is missing from the grip maths rather than held at 1. A trustworthy wheels-off-ground detector is still the prerequisite (the old `WheelSlips ≈ 0` test tripped on decompression), and the dead `_wheelsOffGround` leftover has since been pruned. The throttle-side `WheelsOnGround` rules are the only live part — see the Stability open item.
- **Maneuvers are cards** (`Maneuver` on the racer) — no legacy arm blocks. A card **plays** into the slot, **folds** on its own condition (or the universal stale-armed fold in `ConsiderManeuvers`, evaluated at 1 Hz); with an empty slot the hand is evaluated in priority order and the first playable card plays, and a played card is **never reconsidered mid-play** (unplaying causes thrash). Priority: **ChillOut → DefendLane → DiveBomb → Yield**; **Nitro is slotless** (burn timer + one-per-lap stamp only), resolved before slot cards without blocking them.
  - **ChillOut**: dense pack at the start → halves throttle and pins intended speed to hold station behind the closest rival ahead until the field thins (counts only cars ahead on progress; arms only above a minimum speed so a slow car can't become a rolling roadblock).
  - **DiveBomb**: full throttle into a corner inside its gate, needing an open side (walls tracked per frame in `ApplyRivalWalls`); target = closest overlapping/reachable rival. While active: inside lane beside it, deeper braking target, and a temporary brake-factor bonus (never committed; sampling pauses while any card is active).
  - **DefendLane**: covers the inside against a faster chaser that would reach the entrance no later than we do. **Yield**: caps throttle and halves decel to let a faster overlapping rival by near the entrance.
  - **Corner-commit lane** (DiveBomb/DefendLane) holds for the card's whole life — it runs before the outside-hold check and ignores the latch, the release timer and `SuppressOutsideApproach`, bounded only by the lane method's window and the card's fold.
  - **Nitro situations**: contested / defended / lonely / finish-spender, with vetoes on braking, off-track, big steer angle, low gear on high-geared RWD cars (**AWD exempt**, via the handling struct's drive bias), the **fairness gate** (AI nitro arms only if the player has nitro, unless the player isn't on the grid) and a circuit-wrap veto. Full rationale in `AGENTS-TECHNOTES.md`; the minimum-fire-gear idea is open there too.
- **Passengerize**: AI drivers shift to the passenger seat while a rival overlaps within the combined half-length + a small buffer (prevents contact swerves); never applied to the player. **Ghosting was removed** in the avoidance cleanup — rebuild later with it.

**Duel model (designed via Council, not implemented) — full design in `AGENTS-DUEL.md`.** Physics-aware card play on one shared primitive (predicted time-to-apex per rival from each car's own live plan, not model-stat recomputation; the decel helper is shared with the braking map so the two can't drift; model natives only as the player fallback). This file carries the shipped cards' behaviour only — **anything about rivals, overtaking or card play starts in `AGENTS-DUEL.md`.**

## Durable gotchas — do not "fix" these
- **`if (1 == 2) return;` is an INVERTED gate — it disables nothing.** The return only fires when the condition is true, and it never is, so the guarded code runs. Correct disable idioms: a bare `return;`, or the block form `if (1 == 2) { … }` (as in `Racer.cs`). This bit the start-line flare disable (`bdd1b29`) — flares kept spawning for weeks because of it.
- **Remap with a descending output range + `clamp=true` is inverted** by `Clamp(val, min, max)` when `min > max` (and NaN compares less-than-anything). Keep output clamps ascending; use a descending *input* range for a reversed map. (Bit us repeatedly.)
- **NaN discipline**: `Clamp(NaN, -limit, +limit)` returns the min bound → instant full-lock. Guard steering outputs and any clamp input that can be non-finite. Related: never hand a non-value sentinel (NaN) to a *seeding* getter as its fallback — it writes the sentinel into the ini (found in-game; see `AGENTS-TECHNOTES.md`).
- **A null-check on a freshly `new`-ed object is dead code.** Two "cannot find file" popups lived behind `if (new XmlDocument() == null)`; the real failures (`XmlDocument.Load`, `File.AppendAllText`) *throw* instead, so those paths have **no** error handling — the exception surfaces as a script error.
- Synchronous setup/loading work can pause `OnTick` and temporarily suppress per-frame debug visuals; make setup incremental if that matters.
- **`Handling.Downforce` field: `m_fDownforceModifier` is at `0x0014`.** Source order (`handlingMgr.h`): `0x10` = `m_fInitialDragCoeff`, `0x14` = `m_fDownforceModifier`, `0x18` = `m_fPopUpLightRotation`. `VehicleMemory.GetDownforce` has read `0x0014` since it was added, and the panthere's DF 120 came from that read — so **the code is right**; an earlier revision of this line claiming `0x0010` was a transcription slip off an off-by-one source line number (see AGENTS-TECHNOTES). With the right field, the principled grip divider is `grip /= 1 + 0.035 × Handling.Downforce` (matches the engine's own formula); the old `grip /= 4 + Downforce/100` hack was a curve-fit to the wrong field's range — do not bring it back. Panthere verified end-to-end; derive the rest in `AGENTS-TECHNOTES.md`.
- **Offroad gravity needs a baseline reset before the multiplier.** `Racer.Initialize()` runs every race (and on respawn), so `Handling.Gravity = 9.8f` must be set immediately before the offroad `*= 1.2f`, or it stacks across restarts and inflates every speed/decel site. The reset line is load-bearing.
- **Speed asymmetry is intentional** (see the Speed pipeline). Don't "fix" it.
- **`Intention.CorneringSpeedLimit` is write-only dead state** — assigned in `ComputeTargetSpeed`, read by nobody (not even the debug panel). Changing it, including via Speed Offset, does nothing; the physics cap that actually binds is `followTrackSpd` via `RouteIdealSpeedForRadius`. Wire it into a consumer or prune it — don't tune it.
- **`Options` enum values are positional** — retiring a member renumbers the rest, so never persist or exchange one as an int. Nothing does today (the debug dictionary is keyed on the member, and each toggle's `Menu-Debug.ini` key is its name), which is why past removals stayed harmless; re-check before any numeric consumer appears.
- **`World.DrawMarker` has a per-frame render budget** (found on the input trail): markers issued past it are **silently not drawn**, and draw order decides who loses — oldest-first issue order meant the *newest* 260 of 300 trail markers vanished, which read as "the buffer stopped updating, 300 m adrift with no car at its head". 40 is safe. The budget is shared with every other marker the script draws that frame (edge chevrons, checkpoint rings, join chevron), so a marker visual can break because something *else* got greedy. Long debug geometry belongs in `DRAW_LINE`, which renders at range and is not capped the same way.

- **Two-projection route speed (future idea)** — replace the geometric route speed with a ballistic + a pessimistic projection; caveats in the companion.
- **Off-track projection → reaction relationship — closed (`67d8da7`)**: the reaction used to swing **full throttle → brake inside ~4 m** (±2 m either side of a bound inset by half the car), which is what read aggressive; it now ramps across the **whole track half-width** and past the edge reaches only a shallow floor. Re-checked in game and accepted. The angular-band, binary-gate and pessimistic-projection ideas are **parked, not active**, in `AGENTS-BACKLOG.md`.
- **Immersive join points** — a chevron marks the nearest start line; Context starts a race there (Sprint+Context opens the menu). The join follows **Pace Mode** like any other start.
- **Optional update checker as a separate DLL (idea)**, and **rear-end prevention** tuning notes — both in the companion.
- **Slide brake rampdown — removed for the WIP, reimplement v0.9+**: the brake cap used to ease to 0.8 past `2 + TRlat × 0.2`, a threshold tuned against the *older, smaller* steering allowance; that allowance is now bigger, so the rampdown would bite inside the steering range and the two would ship untuned together. It returns with the first WIP feedback in hand. The cap went **stateful** with it: the full-countersteer release still lands instantly, and the cap now **recovers at the `MaxThrottle` rate** (`+2 × TickScale` in `ConvertSpeedToPedals`) instead of being re-derived to 1 every tick, so full braking returns over ~0.5 s — and it self-heals with no reset, including across the NaN-steer early return. Detail in `AGENTS-BACKLOG.md`.

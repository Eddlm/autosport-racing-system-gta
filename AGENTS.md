## The per-frame pipeline (Racer, timed core)
Rough order, each step consuming the last:
1. `UpdateTrackPosition` — local ±6-node search (global rescan past ~25 m), time-based lookaheads (0.25s→2s), route radii, lap ticks.
2. `ComputeTargetSpeed` — builds the **intended speed** (see Speed pipeline), sets `_cornerSpd` = current corner's apex speed.
3. `ComputeSteering` — resolves the lane (see Lane systems), derives heading/lane/recovery angles, runs the PD to `Control.SteerDegrees`. **The heading-error term is load-bearing — do not remove or merge it into the lane term.** It anchors the car to face the track direction, catching lateral-drift overshoot at the lane center; merging heading + lane into a single "aim at the point" angle was tried and reverted (the car sails past the lane and oscillates).
4. `ApplySteerLimits` — speed-based clamp on steer (only when steer and yaw share sign).
5. `ConvertSpeedToPedals` — the speed loop: intended speed → a single `[-1,1]` combined input, split to throttle/brake, capped/slewed. No reverse routing — forward/brake only; reverse exists solely in the stuck-recovery override. **GridWait lives in three places** — `ComputeTargetSpeed` (pins `Intention.Speed`), `ProcessAI` (handbrake refresh), `TranslateSteerToInput`/`TryGetSteerContext` (steering skip); keep them in sync.
6. `TranslateSteerToInput` — smooths steer toward the target, remaps degrees → -1..1 input. 7. Traction control, maneuvers, stuck recovery run around these.

## Lane systems — where on the track the car aims
Resolved in `ComputeSteering` in this override order (later overrides earlier):
1. **System 2 — high-speed line (`ComputeHighSpeedLane`)**: always runs. Positions the car on the **inside edge of the track's own curvature**, derived purely from track geometry (signed angle between current track direction and a speed-scaled lookahead node ahead) — fully independent of the corner system. Disabled past a radius ceiling (wider = effectively straight).
2. **System 1 — corner outside approach (`ComputeCornerTargetLane`)**: temporary override. Holds the **outside line** only during the approach window before a key corner's apex, then lets go (`0f`) so System 2's inside takes over naturally.
3. **Avoidance (`ComputeAvoidAheadLane`)**: overrides both when a rival ahead needs passing.
4. **`ApplyRivalWalls`**: clamps the final lane between track bounds and rival walls. **Invariants: the car's full width always stays on track; the buffer always includes the average of both cars' bounding boxes (no physical contact possible) + an aggression extra.** Overlap classification uses an asymmetric longitudinal window by design: more margin from a rival ahead (move off them earlier), nearly none from one just passed (crosses back to the racing line as soon as it's clear).

Design rules:
- **Pursuit gain (2026-11)**: lane systems only *set* the target; how hard it's pursued is now uniform — set by the steering lane conversion (below), not per-system radius scaling. The old per-system gain discipline (outside gentler than inside) is gone with the proportional conversion; revisit if outside commits feel too aggressive.
- **Corner approach**: engages only if the car entered the window needing to brake (entry latch); let-go time scales with track width (wider → release earlier). The outside-hold decision is made once per approach, keyed to the apex node, reset after the apex; it can flip from "no hold" to "hold" if the car accelerates into the braking window after a slow entry (e.g., standing-start first corner).
- **Corner-commit maneuvers** (DiveBomb/DefendLane): inside the outside-approach window they replace the outside hold with a lane right beside the target rival on the corner's inside — the divebomber to out-brake an ahead rival, the defender to block a behind rival from diving. Same lane formula, opposite target frame; both clean up when their armed apex is passed (defend also drops on overtake).
- The corner line phases are a **hard switch** (outside → inside), no lerp.

## Gs-aware preview steering (lane error blend)
- **Gs-aware preview steering (lane error blend)**: pure-pursuit steering measures lane error at the *car's current position*, assuming the path follows the nose — but at speed, centrifugal force (already measured in `ProjectAhead`) curves the real path, so nose-aimed steering overshoots. The fix: measure the lane error at the **1s Gs-aware projection** (`ProjectAhead(1f)` vs `LookAhead.OneSec`) instead — the lane error in `ComputeSteering` blends legacy (at the car) with preview; blend 0 = exact legacy (the A/B toggle), blend 1 = full preview.
- **Lane pursuit conversion (proportional, 2026-11)**: lane error (meters) converts to a steering angle by a **fixed degrees-per-meter gain**, clamped to a ceiling that eases with speed (same descending-input Remap pattern as the off-track recovery term) — the old pure-pursuit `atan2(laneError, lookahead)` conversion is gone. Why: its gain was `1/lookaheadDist` with lookahead = speed/grip, so pursuit authority shrank as speed rose (and stretched further as grip degraded) — exactly when lane pursuit felt dead. Degrees-per-meter keeps the intercept angle speed-independent; the ceiling keeps lateral demand sane at high speed; a NaN guard sits before the clamp (`Clamp(NaN)` → min-bound gotcha). Avoidance no longer overrides the conversion distance (its rival-distance lookahead only existed for atan2). `LaneGainExponent` remains dormant for save compatibility. Full removed-curve history in `AGENTS-TECHNOTES.md`.
- **Physical repulsion (velocity-oriented box in `ComputeSteering`, separate from walls)**: inside the box, react only to rivals **actually closing laterally** (rival's relative lateral velocity opposing its side) and **add** a steer-away term to the lane bias — never overwrite the lane bias. Overwriting was tried and broke lane pursuit: parallel traffic (heading angle ≈ 0) coin-flipped the old sign filter and replaced the bias with ~0 — the "lane set but not followed" bug (2026-11). Steer-away magnitude scales with closing speed × distance.
- The projection read in steering is one frame stale (`RunTimedCore` runs before `ProcessTick` refreshes `AccelerationVector`) — same staleness the projection consumers live with; acceptable by design.

## Speed pipeline — how fast the car goes
- **`cornerSpd`** — the "ballpark": kinematic braking plan `√(v²+2·a·d)` targeting the **apex speed**, distance to the **apex node**, plus a flat +5 m/s offset.
- **`followTrackSpd`** — the "precise": route curvature `√(g·grip·radius)` from a time-based lookahead window (three circumradius sample points), plus a flat offset. The window is measured in seconds ahead, not scaled by grip, so it responds consistently at all speeds.
- **Slope grip loss is LIVE** (exponential pitch model, applied to corner + route speed in `ComputeTargetSpeed`); ignore any older note claiming otherwise.
- **Hill/crest grip floors**: `HillGripMin` (slope model, `AutosportRacingSystem.cs`) and the two crest/dip vertical grip factors (route + corner) are tuned together as one knob. **Read the code for the current value; don't trust this file.** (No/low floor → sharp crests can zero out corner speed.)
- **Future-proximate hill → early braking (known issue)**: the slope/crest model reads an upcoming hill and cuts speed before the car reaches it — sudden brakes. Watch when tuning the hill/crest response.
- **`Intention.Speed` = min(cornerSpd, followTrackSpd)**, then clamped by engine top speed, `MaxSpeed`, and the off-track projection cap (`ApplyOffshootBlend`).
- **Pedal gain**: combined input = speed error (m/s) ÷ a full-pedal error divisor (code: `FullPedalSpeedErrorMps`) — full pedal at that error, linear in between; value lives in code. The old Gs-based gain caused under-braking in long braking zones.
- **Off-track projection cap** (`ApplyOffshootBlend`): when the 1 s projection lands outside a corner, the max combined input is capped — full throttle at the inside edge, ramping to a brake floor past the outside edge. Gated by the target lane (no lane → cap doesn't fire); outside judged from the track angle 1 s *behind* so it stays relevant through the corner. Instant clamp, not a decay.
- **Throttle/brake avoidance override: REMOVED** — the old `_accelerationCap` field was scaffolding no system ever pulled down; avoidance/reaction and rear-end prevention rebuild from scratch when needed.
- **Asymmetry is by design**: corner is the loose target, route is the tight one — do not add flat offsets to `followTrackSpd` to "balance" them.
- **High-grip cars don't respond to braking-side tuning**: their braking plan rarely binds — route-curvature speed control wins.

## Corner lifecycle (precomputed apex table + four held targets)
1. **Apex table at generation time** (`BuildApexCorners`, end of `GenerateRouteInfo`): a second pass walks the track **sequentially in chunks**; each chunk's node with the **smallest precise curve radius** is the chunk's apex, kept only under a corner limit. `ARS.Corners` carries only node + radius + tentative 1g speed (`√(g·r)`) — no spans/angles/thresholds (older local-minimum criteria over ±1 then ±4 neighbors produced ~every node as a corner on noisy tracks; the chunked pass fixed it). **Close-corner rule**: within 30 nodes of the previous apex → dropped outright (the two read as one); 30–100 nodes apart → kept but marked `SuppressOutsideApproach` (racers never hold the outside line, nor corner-commit, into it — the approach fights the same braking window). **Gentle-bend rule**: radius over the gentle-bend ceiling → kept but flagged (previously dropped) — the high-speed line governs them. `ComputeCornerTargetLane` matches the flag by apex node against `ARS.Corners` (both instancing paths build synthetic `CornerPoint`s — the flag is looked up, not copied).
2. **Held apex queue per racer** (`UpdateNextApexes`): targets persist until passed, then leapfrog forward and refill by scanning after the last held apex; redundant close apexes skipped unless materially slower; the queue invalidates on route-data changes or a low-speed incident. Per-car apex speed = `√(grip · gravity · radius)`.
3. **Braking map (ApexBrakingSpeed)**: each held apex feeds the kinematic map `v = √(vApex² + 2·a·d)` over the usable distance (apex distance minus a buffer of `ApexBufferSeconds` × corner speed); `cornerSpd = min(map(apex1..4))` — whichever corner demands the lowest speed wins. Buffer is pressure-scaled (0 pressure = brake earlier, 100 = later) and divebomb shortens it.
4. **Route-speed split**: the near window (three sample points, fixed time-ahead span, circumradius) gauges `followTrackSpd` — the authority for **sweeping corners**; the four-apex braking map handles tight ("killer") corners from far away. `Intention.Speed = min(cornerSpd, followTrackSpd)`; the route speed is **no longer gated off** near the apex — both always run, min governs (the old 2s gate caused unawareness in complex curves). **Corner-map handover is positional and unconditional**: the route speed takes over the moment the braking target (entrance node) is passed — no speed condition of any kind (an mph-delta handover braked way too late at angled entrances; a later +Δ-margin condition let the corner map linger and brake inside corners). During the approach the apex braking map keeps full authority; the route speed governs inside the corner. **The apex braking plan is released only once braking is actually done** (`cornerSpd` lifts to route speed only after the entrance node is passed AND the car braked down to corner speed + a small margin — never lingers into the corner, never lets go before the car has genuinely slowed).
5. The old live per-racer rolling scan (`FindNextCorner`) and the far-killer 4s→8s window scan are **superseded** — no code instancing corners from live perception remains. But `Brain.Corner` itself is **live again**: `CommitApexQueue` re-instances it every tick from the nearest held apex (`NextApexNode`), so the outside-approach lane, divebomb/defend, and chevron consumers read live corner state sourced from the apex queue. New consumers may read either; the queue carries more (all four held apexes, radii, per-car speeds).

Track facts: **1 node = 1 m**. Circuit lookaheads use modulo; point-to-point clamps.

The spawned-handle versions are *different* natives (`GET_VEHICLE_ACCELERATION`, `GET_VEHICLE_MAX_TRACTION`) — don't mix them up. Full native hash table in `AGENTS-TECHNOTES.md`.
- **XML supplier files**: `<Model>` InnerText is the **cache key** — usually a signed-int hash for vanilla cars, but a string model name works too (Add-On mods whose hash isn't recognized at native level, e.g. Tiberius = `"tiberius"`). `ModelName` is the friendly model name, not the display name. Power/grip/top-speed are **not** in the XML — they come from the game via the model natives (an **int hash**, not a `Model` object — passing a `Model` crashes); non-numeric `<Model>` cars skip the pace-cache but can still be injected by selection overrides.
- **Stat caches (`ModelGripCache`, `ModelTopSpeedMphCache`)**: the **background** load thread only *discovers* the pool (`RefreshCatalogs` → `VehicleCatalog.FillPool` — pure file I/O into `_vehiclePool`, no natives); `VehicleCatalog.BuildPowerCache` then runs on the **main script thread** after loading to read the model natives and fill model → raw grip (G) + raw top speed (mph). **GTA natives must not be called on the background load thread (`Task.Run`) — that hard-crashes the game.**
- **Pace score (`ModelPaceIndexCache` + `ARS.ComputePaceIndex`)**: raw per-model score (NOT 0–1 — no normalization): `effectiveAccel × 30 + topSpeedMph + grip × 4` (old normalized/ceiling/weights consts were dead code, removed 2026-10). **Electric corrections (user-set assumptions, 2026-10)**: the native **under-reports** electrics, so electric `accelRaw × 3` before the common ×30 slope and electric `topSpeedMph × 0.9` (reported top speed overstates usable racing speed), partially offsetting. `ModelAccelCache` + `ModelElectricCache` (`GET_IS_VEHICLE_ELECTRIC`) fill in `BuildPowerCache`. `BuildPaceIndex` stores the score; `Racer` recomputes at spawn via the shared `ComputePaceIndex` — the leaderboard number equals the selection metric.
- **Selection** (`FillCachedCandidates` → `VehicleSelector.SelectClosestByPace`): one pool pass ranks every paced vehicle by `|pace − target|` against the **effective pace target** and takes the closest grid-size candidates (shuffled for tie-break). It is a **ranking, not a window** — the pace bracket and the widen loop are retired (2026-10), so only a pool with no paced vehicles at all can come up short. The discipline tag **filter is gone** (2026-10) — the pool is every supplier XML under `Vehicles\` (`_vehiclePool`, discovered once at load), while the `<Disciplines>` tags themselves are kept: `ApplyCarAppearance`/`CreateDriverPed`/`ApplyDriverClothes` key the tuner/street looks off them and the track creator writes them. Debug via the log lines "Closest-pace candidates" / "BuildPaceIndex".
- **Dual pace mode (Council-designed, 2026-10)**: `Pace Mode` (Absolute / Relative) + `Pace Offset`. The mode decides only the **anchor** the closest-N fill ranks against. **Relative** (persisted default): anchor resolved once per `InstanceGrid` into local `_resolvedPaceTarget` = `playerPace + PaceOffsetScale` (the offset is deliberately **additive raw score points**; an anchor outside the fleet span is harmless — the ranking simply starts from the closest end). Player pace: `TryComputePlayerCarPaceIndex(out pace)` (NaN-safe; the old `ComputePlayerCarPaceIndex` wrapper is gone with the join override); fallback chain: invalid/on-foot → `_lastKnownPlayerPace` → fixed `PowerTargetScale` + notification. **Absolute** ranks against the fixed persisted target; enable states via `ApplyPaceModeUI`. **Pace Mode is the sole authority on the anchor (2026-10)**: every grid — menu start, restart fallback, E-join — resolves from it, and the join carries no pace override of its own. That override was the old session leak's root, so deleting it retires the class instead of dodging it; consequence to know: an Absolute-mode E-join builds the field around the fixed target, so "race the car you're in" is expressed by choosing Relative. **`PowerTargetScale` is written only by its own menu item and the store restore.** **Pace bracket RETIRED (2026-10)**: closest-N needs no width, so the `Pace Bracket` item, `PowerBracketScale`, `VehicleSelector.Select` and the `Widen Bracket To Fill Grid` dev toggle are deleted; stale `PaceBracket`/`WidenBracketFill` keys in existing inis are never read (harmless legacy). Persistence: `PaceMode` (string, never index) lives in the Settings menu's `Menu-Settings.ini` (moved from `Menu-Race.ini` 2026-10, **no auto-migration — user re-picks manually**; the stale `PaceMode` key in `Menu-Race.ini` is harmless legacy); `PaceOffset`/`PaceTarget` stay in `Menu-Race.ini`, seeded on read; nothing car-dependent is persisted. Full details (offset list spec, ranking-vs-window rationale, NaN ordering hazard) in `AGENTS-TECHNOTES.md`.
- **Always-include pin: REMOVED (2026-09).** `AlwaysIncludeModelNames` + the `VehicleSelector.PinModel` test hook are gone — selection is a pure pace-distance ranking; `VehicleSelector.SelectHardcoded` remains the full-roster bypass (`HardcodedRoster`); rebuild any test pin as config, not code. Full note in `AGENTS-TECHNOTES.md`.
- The leaderboard prefixes each car's name with its raw pace score (`VehicleData.TextPerformanceIndex`, 2 decimals) — the same metric the grid ranks by, not a 0–1 index.

## Per-racer state
- **Aggression** (0–100): grid-assigned (first=0 … last=100, rounded to 10); player stays 50. Scales avoidance extra buffer and allowed TCS wheelspin.
- **Pressure** (0–100): pure proximity × aggression — target ramps from the nearest rival within 100 m; rises slowly, falls quickly. Its old bidirectional `±3 m/s` offset on `followTrackSpd` was removed (cleaner speed pipeline for testing); pressure still drives divebomb/defend/arming and other tactical decisions.
- **Stability-aware grip (`AvgGroundStability`)**: a 0..1 per-racer multiplier on `CurrentMechanicalGrip` (`= Base × Ground × stability`). **Currently hardcoded to 1** — the previous wheels-off-ground detector (`WheelSlips` ≈ 0) was unreliable and triggered on decompression; the field and the decrement/recovery loop are gone from `UpdatePerceivedGrip` until a trustworthy replacement is found. (The separate throttle-side `WheelsOnGround` 3 Hz check is unaffected — it cuts throttle on airborne, a different concern.)
- **Maneuvers as cards** (`Maneuver` on the racer): **all maneuvers are hand cards** — no legacy arm blocks. A card **plays** entering the slot, **folds** ending (own fold or the stale fold). Each tick with an empty `ActiveManeuver` slot the hand is evaluated in priority order and the first playable card plays; a played card is never reconsidered mid-play (no unplaying — that kills thrash). Hand priority: **ChillOut** (first) → **DefendLane** → **DiveBomb** → **Yield**; **Nitro is slotless and resolves instantly** (burn timer + one-per-lap lap stamp are its only state), evaluated before slot cards but never blocking them. Every slot card folds on its own condition, with the **8 s stale-armed fold** in `ConsiderManeuvers` (1 Hz) as the universal backstop: DiveBomb/DefendLane fold when their armed apex is passed (DefendLane also when the chaser stops trailing — gone, despawned, or no longer Behind), ChillOut when the pack thins, Yield per-tick (fastest-responding) when the target drifts beyond its exit distance. Nitro's burn is fixed-length by physics. **Corner-commit lane (DiveBomb/DefendLane)**: the beside-the-rival inside line in `ComputeCornerTargetLane` holds for the card's whole life — before the outside-approach hold check, ignoring the hold latch, release timer, and `SuppressOutsideApproach` — bounded only by the lane method's 5 s-to-apex window and the card's fold. Divebomb draws a per-dive brake bonus (whole hundredths, appended to the learned factor for that dive only, never committed).
  - **ChillOut**: dense pack (rival count within a crowd radius ≥ threshold — race starts) → halves throttle, pins intended speed to hold a standoff behind the closest rival ahead until the field thins. Crowd count reads the whole field (`ARS.Racers`), counting only cars **ahead on race progress**; arms only above a minimum own speed (a slow car must not pin itself into a rolling roadblock; the leader has nobody to crowd).
  - **DiveBomb**: fires at full throttle into a corner within its seconds gate, at most one rival wall active (an open side to commit — walls are the `ApplyRivalWalls` corridor, count tracked per frame there); target = closest rival we overlap or reach within its reach-seconds window (`TimeToContact`). While active: inside lane beside the target, braking target deepened toward the corner, effective brake factor = learned factor + temp bonus (never committed; sampling pauses while any card is active).
  - **DefendLane**: covers the inside against a faster chaser that would reach the corner entrance no later than us. **Yield**: caps throttle and halves decel to let a faster, overlapping, higher-pressure rival by near the entrance.
  - **Nitro card situations**: contested (rival nearby and faster), defended (rival behind closing within the burn's reach), lonely (empty straight, slow, next apex far), finish spender (race almost over — skips the corner-entrance gate). Vetoes: braking, off-track, big steer angle, low gear on high-geared RWD cars (wheelspin — **AWD exempt**, via handling `fDriveBiasFront` at `0x48` between 0 and 1; offset anchored by the same struct math verified at steering lock `0x80` / traction-lateral `0x98`), the **fairness gate** (`ARS.PlayerParticipating` — AI nitro only arms when the player has nitro, unless the player isn't on the grid), and the circuit-wrap veto (the corner gate never fires inside the armed corner's span — the lap-wrap made a just-behind entrance read a full lap away). Full veto rationale in `AGENTS-TECHNOTES.md`; future idea: compute the true minimum fire gear from power multiplier vs wheel grip instead of the fixed gear veto.

- **Passengerize**: AI drivers shift to the passenger seat while a rival overlaps within combined half-length + 0.5 m, preventing contact swerves. Never applied to the player.
- Ghosting was removed during avoidance cleanup; rebuild later with the avoidance system.

**Duel model (designed via Council, not yet implemented) — full design in `AGENTS-DUEL.md`.** Physics-aware card play on one shared primitive (predicted time-to-apex per rival from each car's own live plan — not model-stat recomputation; decel helper shared with `ApexBrakingSpeed` so the duel and speed pipeline can't drift; model-hash natives only as player fallback). Council-endorsed card upgrades: DiveBomb exchange-completion gate, DefendLane threat check, Yield corner-superiority (+ race-progress gate), nitro segment advantage (+ `RelativePosition` filter fix). Hazards/guard rails and the 4-step in-game-verified sequencing are in the companion — read it before touching any card logic.

## Durable gotchas — do not "fix" these
- **`if (1 == 2) return;` is an INVERTED gate — it disables nothing.** The return only fires if the condition is true, and it never is, so the guarded code runs. Correct disable idioms: an unconditional `return;`, or the block form `if (1 == 2) { … }` (as in `Racer.cs`). This bit the start-line flare disable (commit `bdd1b29`) — flares kept spawning for weeks because of it.
- **Remap with a descending output range + `clamp=true` is inverted** by `Clamp(val, min, max)` when `min > max` (NaN also compares less-than-anything). Keep output clamps ascending — use a descending *input* range for a reversed map. (This bit us repeatedly.)
- **NaN discipline**: `Clamp(NaN, -limit, +limit)` returns the min bound → instant full-lock. Guard steering outputs and any clamp input that can be non-finite.
- Synchronous setup/loading work can pause `OnTick` and temporarily suppress per-frame debug visuals; make setup incremental if that matters.
- **Speed asymmetry** (above) is intentional.
- **`Handling.Downforce` reads the wrong handling field.** `VehicleMemory.GetDownforce` must read `m_fDownforceModifier` at struct offset `0x0010` — the old `0x0014` read was `m_fPopUpLightRotation` (the panthere's "raw 258" was that field; real `m_fDownforceModifier` is 120). With the offset corrected, the **principled grip divider** in `UpdatePerceivedGrip` is `grip /= 1 + 0.035 × Handling.Downforce` (matches the engine's `CommandGetVehicleMaxTraction` formula); the old empirical `grip /= 4 + Downforce/100` hack was a curve-fit to the wrong offset's value range — do not bring it back. **Panthere verified end-to-end**; sample more raw-downforce > 100 cars before calling it universally closed. Full derivation in `AGENTS-TECHNOTES.md`.
- **Offroad gravity bump requires a baseline reset before the multiplier.** `Racer.Initialize()` runs every race (and on respawn paths); without `Handling.Gravity = 9.8f` immediately before the offroad conditional, the `*= 1.2f` stacks across restarts — `GRV` drifts upward and inflates every speed/decel site. The reset line is load-bearing.

## The per-frame pipeline (Racer, timed core)
Order, each step consuming the last:
1. `UpdateTrackPosition` — local ±6-node search (global rescan past ~25 m), time-based lookaheads, route radii, lap ticks.
2. `ComputeTargetSpeed` — builds the **intended speed** (Speed pipeline), sets `_cornerSpd` from the current corner.
3. `ComputeSteering` — resolves the lane (Lane systems), derives heading/lane/recovery angles, runs the PD to `Control.SteerDegrees`. **The heading-error term is load-bearing — do not remove or merge it into the lane term.** It anchors the car to the track direction and catches lateral-drift overshoot at lane centre; merging heading + lane into one "aim at the point" angle sails past the lane and oscillates (tried, reverted).
4. `ApplySteerLimits` — speed-based steer clamp (only when steer and yaw share sign).
5. `ConvertSpeedToPedals` — intended speed → one `[-1,1]` combined input, split to throttle/brake, capped/slewed. **No reverse routing** (forward/brake only; reverse exists solely in stuck recovery). **GridWait lives in three places** — `ComputeTargetSpeed` (pins `Intention.Speed`), `ProcessAI` (handbrake refresh), `TranslateSteerToInput`/`TryGetSteerContext` (steering skip); keep them in sync.
6. `TranslateSteerToInput` — smooths steer toward target, remaps degrees → -1..1. Traction control, maneuvers and stuck recovery run around these.

## Lane systems — where on the track the car aims
Resolved in `ComputeSteering`, later overrides earlier:
1. **High-speed line (`ComputeHighSpeedLane`)** — always runs; puts the car on the **inside edge of the track's own curvature**, from geometry only (signed angle between the track direction and a speed-scaled lookahead node). Disabled past a radius ceiling (wide ≈ straight).
2. **Corner outside approach (`ComputeCornerTargetLane`)** — temporary override; holds the **outside line** during the approach window before a key apex, then releases (`0f`) so the inside line takes over.
3. **Avoidance (`ComputeAvoidAheadLane`)** — overrides both when a rival ahead needs passing.
4. **`ApplyRivalWalls`** — clamps the final lane between track bounds and rival walls. **Invariants: the car's full width always stays on track; the buffer always includes the average of both bounding boxes (no physical contact possible) + an aggression extra.** The overlap window is asymmetric by design: generous from a rival ahead, nearly none from one just passed.

Design rules:
- **Lane systems only *set* the target; how hard it is pursued is uniform**, set by the steering lane conversion (below) — the old per-system gain discipline is gone with the proportional conversion. Revisit only if outside commits feel too aggressive.
- **Corner approach** engages only when the car entered the window needing to brake (entry latch); let-go time scales with track width. The hold decision is made once per approach (keyed to the apex node, reset after it) and can flip to "hold" if the car accelerates into the braking window after a slow entry.
- **Corner-commit maneuvers** (DiveBomb/DefendLane) replace the outside hold with a lane beside the target rival on the corner's inside — same formula, opposite target frame; both clean up when their apex is passed (defend also on overtake).
- The corner line phases are a **hard switch** (outside → inside), no lerp.

## Gs-aware preview steering (lane error blend)
- Nose-aimed steering measures lane error at the car's position, but at speed centrifugal force (already measured by `ProjectAhead`) curves the real path, so it overshoots. The lane error in `ComputeSteering` therefore blends legacy (at the car) with the **1 s Gs-aware projection**; blend 0 = exact legacy, blend 1 = full preview.
- **Lane pursuit conversion (proportional, 2026-11)**: lane error (metres) → steer angle by a **fixed degrees-per-metre gain**, clamped to a ceiling that eases with speed (descending-input Remap). The old `atan2(laneError, lookahead)` is gone: its gain was `1/lookaheadDist` with lookahead = speed/grip, so authority shrank exactly when speed rose or grip fell. A NaN guard sits before the clamp. `LaneGainExponent` is dormant for save compatibility; removed-curve history in `AGENTS-TECHNOTES.md`.
- **Physical repulsion** (velocity-oriented box, separate from walls): inside it, react only to rivals **actually closing laterally** and **add** a steer-away term to the lane bias — never overwrite the bias (overwriting broke lane pursuit: parallel traffic made the sign filter coin-flip and replaced the bias with ~0). Magnitude scales with closing speed × distance.
- The projection read is one frame stale by design (`RunTimedCore` runs before `ProcessTick` refreshes `AccelerationVector`) — same staleness all projection consumers accept.

## Speed pipeline — how fast the car goes
- **`cornerSpd`** — the "ballpark": kinematic braking plan `√(v²+2·a·d)` toward the **apex speed**, over the distance to the **apex node**. No flat offset of its own.
- **`followTrackSpd`** — the "precise": route curvature `√(g·grip·radius)` from a time-based lookahead window (three circumradius sample points). The window is in seconds ahead, not grip-scaled, so it responds consistently at all speeds.
- **Slope grip loss is LIVE** (exponential pitch model applied to corner + route speed); ignore any older note claiming otherwise. Hill/crest grip floors (the slope model's floor plus two vertical grip factors) are tuned as one knob — **read the code for current values**. Known issue: the model reads an upcoming hill and cuts speed before the car reaches it (sudden brakes).
- **`Intention.Speed` = min(cornerSpd, followTrackSpd) + Speed Offset**, then clamped by engine top speed, `MaxSpeed`, and the off-track projection cap. **Speed Offset** (AI Settings → `Menu-Racers.ini`, even mph −10…+10, default 0) is the pipeline's *only* flat fudge and is applied once at the end, so it also lifts apex-limited speed — apex speed itself stays pure physics `√(grip·gravity·radius)`. The old hardcoded +8 here and +6 on the route term were removed; chicane's +10 stays.
- **Pedal gain**: combined input = speed error ÷ a full-pedal error divisor (code: `FullPedalSpeedErrorMps`) — full pedal at that error, linear between. The old Gs-based gain under-braked in long braking zones.
- **Off-track projection cap (`ApplyOffshootBlend`)**: when the 1 s projection lands outside a corner, the max combined input is capped — full throttle at the inside edge, ramping to a brake floor past the outside edge. Gated by the target lane (no lane → no cap); "outside" is judged from the track angle 1 s *behind* so it stays relevant through the corner. Instant clamp, not a decay.
- **Throttle/brake avoidance override: REMOVED** (the old `_accelerationCap` was scaffolding nothing pulled down). **Asymmetry is by design**: corner is the loose target, route the tight one — do not "balance" them with flat offsets. **High-grip cars don't respond to braking-side tuning**; route-curvature control wins.

## Corner lifecycle (precomputed apex table + four held targets)
1. **Apex table at generation** (`BuildApexCorners`, end of `GenerateRouteInfo`): a second pass walks the track **sequentially in chunks** and takes each chunk's smallest precise radius as its apex, kept only under a corner limit. `ARS.Corners` holds node + radius + tentative 1g speed only (older local-minimum criteria over ±1 then ±4 neighbours made every noisy node a corner; the chunked pass fixed it). **Close-corner rule**: within 30 nodes of the previous apex → dropped (they read as one); 30–100 nodes → kept but flagged `SuppressOutsideApproach` (no outside hold, no corner-commit). **Gentle-bend rule**: over the gentle-bend ceiling → kept but flagged; the high-speed line governs. `ComputeCornerTargetLane` looks the flag up by apex node (not copied).
2. **Held apex queue per racer** (`UpdateNextApexes`): targets persist until passed, then leapfrog and refill; redundant close apexes skipped unless materially slower; the queue invalidates on route-data change or a low-speed incident. Per-car apex speed = `√(grip · gravity · radius)`.
3. **Braking map (`ApexBrakingSpeed`)**: each held apex feeds `v = √(vApex² + 2·a·d)` over the usable distance (apex distance minus a buffer of seconds × corner speed); `cornerSpd = min(map(apex1..4))` — the lowest demand wins. The buffer is pressure-scaled and divebomb shortens it.
4. **Route-speed split**: the near window gauges `followTrackSpd` — the authority for **sweeping corners** — while the four-apex map handles tight corners from far away. Both always run; **min governs** (the old 2 s gate caused unawareness in complex curves). **Handover is positional and unconditional**: route speed takes over the moment the braking target (entrance node) is passed, with no speed condition (an mph-delta handover braked far too late; a margin condition let the corner map brake inside corners). **The apex plan is released only once braking is genuinely done** (entrance passed AND the car at corner speed + a small margin).
5. The old live rolling scan and the far-killer window scan are **superseded**. But `Brain.Corner` is **live again**: `CommitApexQueue` re-instances it each tick from the nearest held apex, so outside-approach, corner-commit and chevron consumers read live state sourced from the queue. New consumers may read either; the queue carries more.

Track facts: **1 node = 1 m**. Circuit lookaheads use modulo; point-to-point clamps.

- **Threading contract**: the background load thread only *discovers* the pool (`RefreshCatalogs` → `VehicleCatalog.FillPool`, pure file I/O into `_vehiclePool`); `BuildPowerCache` then runs on the **main thread** to read the natives. **Calling GTA natives on the background thread hard-crashes the game.**
- **Pace score** (`ModelPaceIndexCache` + `ComputePaceIndex`): a raw per-model score, **not** 0–1 (`effectiveAccel × k + topSpeedMph + grip × k2`; the old normalized/ceiling/weights consts were dead code, removed 2026-10). Electric cars get an accel multiplier and a top-speed discount because the native under-reports them — user estimates, unverified in-game. `Racer` recomputes at spawn with the same function, so **the leaderboard number equals the selection metric**.
- **PI ballpark in the menus (2026-11)**: the PI Target and PI Offset descriptions append three example cars — nearest at or below the value, nearest overall, nearest at or above — read from `ModelPaceIndexCache` and named via `ModelNameCache`. That cache resolves the **GXT label** the model native returns (`GET_DISPLAY_NAME_FROM_VEHICLE_MODEL` → "SABREGT") through `Game.GetGXTEntry` to get the readable name, falling back to the roster line for an add-on the game can't resolve. The offset's trio is `playerPace + offset` and is omitted while the player is on foot; `ApplyPaceModeUI` is the single writer of both descriptions (it also carries a null guard — the item handlers can fire mid-build).
- **Selection** (`FillCachedCandidates` → `SelectClosestByPace`): one pool pass ranks every paced model by `|pace − target|` and takes the closest N (shuffled for tie-break), returning **model keys** — no file is touched. It is a **ranking, not a window** — the pace bracket, the widen loop and `VehicleSelector.Select` are retired.
- **Pace Mode is the sole authority on the anchor (2026-10)**: Relative resolves `playerPace + PaceOffsetScale` once per grid; Absolute uses the persisted fixed target. Every grid — menu start, restart fallback, E-join — resolves from the mode, and the join carries **no pace override of its own** (that override was the old session leak's root, deleted rather than dodged). Consequence: an Absolute-mode E-join fields the fixed target; "race the car you're in" is chosen by choosing Relative. `PowerTargetScale` has exactly two writers — its own menu item and the store restore in `RefreshPowerControls`. Fallback chain when `TryComputePlayerCarPaceIndex` can't resolve the player's pace: `_lastKnownPlayerPace` → fixed target + notification. Full offset spec, ranking-vs-window rationale and the NaN-ordering hazard in `AGENTS-TECHNOTES.md`; pace-theory vs instance measurement in `AGENTS-BACKLOG.md`. **Menu vocabulary (2026-11): the items are `Grid PI Mode` / `PI Offset` / `PI Target` and the mode is a real `PaceMode` enum stored as `Absolute` / `RelativeToMine` — the *labels* say PI, the *keys* (`PaceMode`/`PaceOffset`/`PaceTarget`) and the code keep the name pace.**
- **Always-include pin: REMOVED (2026-09)** — selection is pure pace distance; `SelectHardcoded` remains the full-roster test bypass.
- The leaderboard prefixes each car with its raw pace score (2 decimals) — the same metric the grid ranks by.

## Per-racer state
- **Aggression** (0–100): grid-assigned by position (first lowest … last highest); the player stays mid. Scales the avoidance buffer and allowed TCS wheelspin.
- **Pressure** (0–100): proximity × aggression — ramps from the nearest rival inside a radius; rises slowly, falls quickly. Its old `±3 m/s` offset on `followTrackSpd` was removed; pressure still drives divebomb/defend/arming.
- **Stability-aware grip (`AvgGroundStability`)**: a multiplier on `CurrentMechanicalGrip` (`Base × Ground × stability`) — **hardcoded to 1** until a trustworthy wheels-off-ground detector exists (the old `WheelSlips ≈ 0` test tripped on decompression). The throttle-side `WheelsOnGround` check is separate and live.
- **Maneuvers are cards** (`Maneuver` on the racer) — no legacy arm blocks. A card **plays** into the slot, **folds** on its own condition (or the universal stale-armed fold in `ConsiderManeuvers`, evaluated at 1 Hz); with an empty slot the hand is evaluated in priority order and the first playable card plays, and a played card is **never reconsidered mid-play** (unplaying causes thrash). Priority: **ChillOut → DefendLane → DiveBomb → Yield**; **Nitro is slotless** (burn timer + one-per-lap stamp only), resolved before slot cards without blocking them.
  - **ChillOut**: dense pack at the start → halves throttle and pins intended speed to hold station behind the closest rival ahead until the field thins (counts only cars ahead on progress; arms only above a minimum speed so a slow car can't become a rolling roadblock).
  - **DiveBomb**: full throttle into a corner inside its gate, needing an open side (walls tracked per frame in `ApplyRivalWalls`); target = closest overlapping/reachable rival. While active: inside lane beside it, deeper braking target, and a temporary brake-factor bonus (never committed; sampling pauses while any card is active).
  - **DefendLane**: covers the inside against a faster chaser that would reach the entrance no later than we do. **Yield**: caps throttle and halves decel to let a faster overlapping rival by near the entrance.
  - **Corner-commit lane** (DiveBomb/DefendLane) holds for the card's whole life — it runs before the outside-hold check and ignores the latch, the release timer and `SuppressOutsideApproach`, bounded only by the lane method's window and the card's fold.
  - **Nitro situations**: contested / defended / lonely / finish-spender, with vetoes on braking, off-track, big steer angle, low gear on high-geared RWD cars (**AWD exempt**, via the handling struct's drive bias), the **fairness gate** (AI nitro arms only if the player has nitro, unless the player isn't on the grid) and a circuit-wrap veto. Full rationale in `AGENTS-TECHNOTES.md`; the minimum-fire-gear idea is open there too.
- **Passengerize**: AI drivers shift to the passenger seat while a rival overlaps within the combined half-length + a small buffer (prevents contact swerves); never applied to the player. **Ghosting was removed** in the avoidance cleanup — rebuild later with it.

**Duel model (designed via Council, not implemented) — full design in `AGENTS-DUEL.md`.** Physics-aware card play on one shared primitive (predicted time-to-apex per rival from each car's own live plan, not model-stat recomputation; the decel helper is shared with the braking map so the two can't drift; model natives only as the player fallback). Read the companion before touching card logic.

## Durable gotchas — do not "fix" these
- **`if (1 == 2) return;` is an INVERTED gate — it disables nothing.** The return only fires when the condition is true, and it never is, so the guarded code runs. Correct disable idioms: a bare `return;`, or the block form `if (1 == 2) { … }` (as in `Racer.cs`). This bit the start-line flare disable (`bdd1b29`) — flares kept spawning for weeks because of it.
- **Remap with a descending output range + `clamp=true` is inverted** by `Clamp(val, min, max)` when `min > max` (and NaN compares less-than-anything). Keep output clamps ascending; use a descending *input* range for a reversed map. (Bit us repeatedly.)
- **NaN discipline**: `Clamp(NaN, -limit, +limit)` returns the min bound → instant full-lock. Guard steering outputs and any clamp input that can be non-finite. Related: never hand a non-value sentinel (NaN) to a *seeding* getter as its fallback — it writes the sentinel into the ini (found in-game; see `AGENTS-TECHNOTES.md`).
- **A null-check on a freshly `new`-ed object is dead code.** Two "cannot find file" popups lived behind `if (new XmlDocument() == null)`; the real failures (`XmlDocument.Load`, `File.AppendAllText`) *throw* instead, so those paths have **no** error handling — the exception surfaces as a script error.
- Synchronous setup/loading work can pause `OnTick` and temporarily suppress per-frame debug visuals; make setup incremental if that matters.
- **`Handling.Downforce` reads the wrong handling field if you use `0x0014`.** `VehicleMemory.GetDownforce` must read `m_fDownforceModifier` at **`0x0010`** (the old offset was `m_fPopUpLightRotation` — the panthere's "raw 258" was that field; real downforce is 120). With that fixed, the principled grip divider is `grip /= 1 + 0.035 × Handling.Downforce` (matches the engine's own formula); the old `grip /= 4 + Downforce/100` hack was a curve-fit to the wrong field's range — do not bring it back. Panthere verified end-to-end; derive the rest in `AGENTS-TECHNOTES.md`.
- **Offroad gravity needs a baseline reset before the multiplier.** `Racer.Initialize()` runs every race (and on respawn), so `Handling.Gravity = 9.8f` must be set immediately before the offroad `*= 1.2f`, or it stacks across restarts and inflates every speed/decel site. The reset line is load-bearing.
- **Speed asymmetry is intentional** (see the Speed pipeline). Don't "fix" it.
- **`Intention.CorneringSpeedLimit` is write-only dead state** — assigned in `ComputeTargetSpeed`, read by nobody (not even the debug panel). Changing it, including via Speed Offset, does nothing; the physics cap that actually binds is `followTrackSpd` via `RouteIdealSpeedForRadius`. Wire it into a consumer or prune it — don't tune it.

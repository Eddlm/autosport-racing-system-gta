## AI and race behavior
- Ghosting was removed during avoidance cleanup; rebuild it later with the avoidance system.
- Passengerize: AI drivers move to the passenger seat while a rival is within combined half-length + 0.5m, preventing GTA V contact swerves. Restore driver seat when clear; never apply to player.
- Avoidance: independent left (negative) and right (positive) walls snap to nearby rivals, then open at 2 m/s. Car edges respect walls; lift off if gap < car width + 1m. Ignore a rival behind when heading difference exceeds 20°.
- Aggression: 0–100, player remains 50; grid assigns first=0 through last=100, rounded to 10. It scales avoidance buffer (2 m→0.25 m) and allowed TCS wheelspin (0.5→1.5; base 1.0 ±0.5). Leaderboard shows purple `(aggro)`.
- Braking uses `v₀ = √(vTarget² + 2·decel·distance)`; decel is `brakingAbility * 4 * gravity * 0.5`. The `+1 m/s` overdrive was removed (1 Aug 2026) — the plan is now strictly kinematic. Take the minimum with route-curvature speed. Since 2 Aug 2026, `vTarget` is the **apex speed** and `distance` is measured to the **apex node** (`c.Node`) rather than the corner entry (`c.Node - c.LengthStart`) — brake-to-apex targeting. Since 7 Aug 2026 the safety margin is `cornerSpeed × BrakingCoastSecondsBeforeApex` (1 s): the car reaches corner speed 1 s before the apex and coasts the rest — margin scales with corner speed (tried fixed 20 m same day, rejected as wrong feel).
- Corner speed scans every corner node for the tightest `PreciseCurveRadius`; precise/general radius windows are ±4/±10 nodes and use full grip.
- Route curvature samples from `RouteWindowStart`, speed-based — pressure-driven since 7 Aug 2026 (see Pressure-driven lookahead). Hill grip was removed from `ComputeRouteSpeed` (1 Aug 2026); slope loss is now a separate power-law factor applied after the route-speed computation.
- Steering uses one wall-respecting lane bias. Its speed limiter applies only when steer/yaw have the same sign; output is ×0.9 with 1° minimum.
- Corner line phases: center (>5 s), outside (5–2 s), lerp outside→inside (2–1.33 s), inside (1.33 s pre-apex aim through apex). Pull uses 1–2 s lookahead curvature. (1 Aug 2026, turnInTime updated 7 Aug 2026)
- Inside intensity remap (1 Aug 2026): `Remap(curveRadius, 100, 1000, 1.0, 0.1, clamp=true)`. Clamp is built into the Remap (single source of truth — do not add a separate `Clamp` call). Below 100m → 1.0 (full inside), above 1000m → 0.1 (barely off center). Pushes the "full inside" zone out to 100m+ radii so the AI commits to a real inside line on a much wider range of corners.
- Understeer throttle cap (1 Aug 2026): graduated pedal response. `_steerOver = requestedSteer - clampedSteer` (signed, in degrees) is stored in `ApplySteerLimits`. In `ConvertSpeedToPedals` (gated on `currentForwardSpeed > 10f` and `_steerCapped`): `understeerThrottleCap = Clamp(-_steerOver / 5f, -1f, 1f)`. Maps -5° under cap → +1 (full throttle), at cap → 0, +5° over cap → -1 (full brake). Positive part multiplies throttle; negative part's magnitude becomes the MINIMUM brake input (floor via `max(newBrake, -min(cap, 0))`). Throttle cut + brake floor = "lift when near the limit, brake when over the limit". Symmetric across left/right (sign of `_steerOver` cancels).
- **Unified `AccelerationCap` (2 Aug 2026)**: single float in `[-1, +1]`. +1 = full throttle, 0 = coast, -1 = full brake. Re-rises at 0.33/s toward +1 each frame (frame-independent via `TickScale`). Each "lift off" source lowers via `Math.Min`; applied once in `ConvertSpeedToPedals`. **Replaces the old `understeerThrottleCap` local and the `_avoidLiftOff` bool** as the unified input cap. **All sources are smooth mappings, never binary.** Currently three sources: steer-in (`Clamp(1 - _steerOver / 5, 0, 1)`, ramps from +1 at the cap to 0 at +5° over — **no brake from understeer, only lift**), avoidance (`Remap(rivalDistance, 0, 5, -1, 1, clamp)`, 5m → +1, 0m → -1, lifts or brakes proportionally as a rival closes), and projection off-track (see the `ProjectAhead()` entry for the formula). Sources SET the cap, the rise only fills the gap. "Only replace if lower" — never override an active source.
- **`ProjectAhead()` (2 Aug 2026)**: 1-second kinematic projection on the racer — `pos + v*t + 0.5*a*t²` with t=1, where a is the average of the last ~10 frames' world-frame accelerations from `UpdateTickData`. Returns `Vector3`, world space, 3D. Used in debug visualization (white line + sphere from car in `showAggro`; sphere flips red, track edges drawn green/red) **and** as the third `AccelerationCap` source: `projectionScalar = 1 - 0.2·max(0, distanceFromInside - trackWidth)`, where `distanceFromInside` = `cornerDir · SignedLaneOffset(projectedPos, nearestTrackPoint)` + `TrackHalfWidth` (lateral offset from the corner's **inside** edge — only the outside is penalized). Penalty starts only once the projected position is past the **full track width**, at 0.2 per meter beyond. The scalar is floored by `Remap(speed, followTrackSpd, followTrackSpd - 20, -1, +1, clamp)`: at/above target speed the floor pins it to +1 (trajectory penalty suppressed — the kinematic speed loop alone handles overspeed); full braking is only allowed once ≥20 m/s under target. Applied via `Math.Min` like the other sources.
- Debug: ShowTrack draws only start/apex/end green chevrons + apex radius (R) and speed (SPD) text; ShowInputs draws green/white/red pedal trail + lane debug. ShowAggro and ShowPhysics default off.
- AI nitrous visual/cheat-power prototype exists but must remain disabled with `AiNitrousEnabled = false` pending tuning.
- Pressure (31 Jul 2026): per-racer 0–100 state, updated during a race from nearby racers within 100 m. It ramps toward its crowd-adjusted aggression target at 15/s and falls at 30/s; after two nearby racers, each extra racer deducts `max(1, (100 - Aggression) / 10)` from the target. With exactly two cars together, `nearbyRacers = 1` so `targetPressure = Aggression` — no crowd penalty — meaning aggressive duos run near-max pressure. Pressure adds a fixed overspeed: `followTrackSpd += 5 · Pressure/100` (max 5 m/s at Pressure=100).
- Braking overdrive (removed 1 Aug 2026): the old `cornerSpd = MaxSpeedForBrakingDistance + 1f` (+1 m/s overdrive) was stripped. The braking plan is now strictly kinematic.
- Hill grip (1 Aug 2026): the old `HillGripMultiplierFromVelocity` and `HillGripDeltaGs` were removed from `UpdatePerceivedGrip` — `CurrentMechanicalGrip` is now pure `baseGrip × groundMultiplier`, with no hill-based grip modifier baked into the grip value itself. Instead, a new slope power-law loss `loss = 3 · θ²` (θ in radians) is computed at the follow point and applied as a speed factor `√(1 − loss)` to **both** `cornerSpd` and `followTrackSpd` in `ComputeTargetSpeed`, before the pressure overspeed.
- Pressure offset cap (1 Aug 2026): `PressureMaxSpeedOffset = 5f` m/s. `followTrackSpd += 5 · Pressure/100` — a fixed overspeed, purely proportional to pressure (0 at 0, 2.5 m/s at 50, 5 m/s at 100 = 11 mph), always applied (no gate). The radius-delta dependency and the old gate were removed — the offset is just pressure × constant.
- Speed target asymmetry (1 Aug 2026): `cornerSpd` is the "ballpark" speed (kinematic braking plan, slope-grip, +3 m/s flat offset), while `followTrackSpd` is the precise dynamic speed (slope-grip, vertical curvature, pressure overspeed). They're intentionally asymmetric: corner is a loose target the route can lower; route is the tight one the min takes. Do not add a flat offset to followTrackSpd to "balance" them — the asymmetry is by design.

## Blow-through analysis (1 Aug 2026) — cars together blow through corners
- Question: what makes a pack blow a corner? Suspected a speed override/offset from pressure or avoidance.
- **Proven (code):** the corner speed guard releases at the apex for every car. `GetNextCorner(currentNode)` returns the first key corner with `Node > currentNode`, so the instant `currentNode >= apex` the target flips to the next corner. `MaxSpeedForBrakingDistance` then measures to that far entry → `cornerSpd` becomes huge → from apex to the next braking zone, the current corner's speed cap is gone and speed is `min(huge, followTrackSpd)` = pure route curvature + pressure blend. Steering does *not* release at the apex (`ComputeCornerTargetLane` keeps `insideTarget` while `Node >= apexNode`), so the AI holds the inside line with no speed cap. This is pack-independent.
- **Proven pack-specific aggravators (code):** `Pressure` is proximity-driven (`UpdatePressure`), so a duo runs near `Aggression`; `_avoidLiftOff` only brakes when a rival is directly ahead (side-by-side = no brake at all), and when it does fire it caps to the leader's *live* (already too fast) speed — avoidance propagates speed, it never raises it.
- **Not proven / retracted:** earlier claim that pack shoving → tracker node jumps → premature corner retarget. The tracker (`UpdateTrackPosition`) searches ±6 nodes and only globally rescans when the closest local candidate exceeds `max(TrackHalfWidth + 10, 25)` m; a 25 m+ deviation is not established for side-by-side racing. Do not cite this without in-game telemetry.
- Working theory: blow-through is apex-release of the corner cap (all cars) amplified by pressure raising the follow-track speed (pack duos near max pressure). Not confirmed in-game yet.
- **Avoidance throttle-lift (1 Aug 2026):** when cars are corraled between rivals and the avoidance walls collapse (gap < car width), `_avoidLiftOff` triggers. If there's a rival directly ahead, the AI caps its speed to that rival's speed — "I can't get past so I'll match the leader." This is a defensive throttle-lift, not aerodynamic. In a pack corner, if the leader is already going too fast (blow-through), the follower matches that speed rather than braking to a safe corner speed.

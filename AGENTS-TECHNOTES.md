## Nitrous system facts (researched, The Contract-era natives)

- "Vehicle has nitrous" = **vehicle mod slot 17** (`VMT_NITROUS`); detect with `GET_VEHICLE_MOD(veh, 17) != -1`.
- Nitrous natives — all plain game-binary VEHICLE natives, SP-safe raw-hash calls:
  - `SET_OVERRIDE_NITROUS_LEVEL` `0xC8E9B6B71B8E660D` — **pass all 6 args** (2-arg calls zero level/power/recharge on b2060+)
  - `FULLY_CHARGE_NITROUS` `0x1A2BCC8C636F9226`
  - `CLEAR_NITROUS` `0xC889AE921400E1ED`
  - `IS_NITROUS_ACTIVE` `0x491E822B2C464FE4` (BOOL, firing now)
  - `_GET_REMAINING_NITROUS_DURATION` `0xBEC4B8653462450E` (float charge)
  - `SET_NITROUS_IS_ACTIVE` `0x9E566EA551F4F1A6`
  - `_SET_NITROUS_IS_VISIBLE` `0x465EEA70AF251045`
  - `_SET_REMAINING_NITROUS_DURATION` `0x1AD0F63A94E10EFF`
  - `_SET_VEHICLE_USE_HORN_BUTTON_FOR_NITROUS` `0x1980F68872CC2C3D` (global horn→nitrous)
- Installed state persists in mod data; charge is runtime-only per entity.
- Vanilla SP LS Customs does **not** sell nitrous (Online feature); in SP slot 17 is set only by trainers/modded shops.
- **Verified in-game**: `_GET_REMAINING_NITROUS_DURATION` is useless for detection (always ~full, drops only on fire, never recharges); trainer-forced nitro has no detectable installed state — the only fire-side signal is `IS_NITROUS_ACTIVE`.
- **ARS detection is a per-race latch** (`PlayerHasNitro`): set on slot 17, on `IS_NITROUS_ACTIVE`, or on a below-full charge; cleared at each `StartRace`.
- **Menyoo 2.0 source audit** (cloned `itsjustcurtis/MenyooSP` → `_research\Menyoo2`): declares the full set but **calls none of it** — "Race Boost On Horn" is fake (`SET_VEHICLE_BOOST_ACTIVE` one frame + raw force + hand-rolled NOS PTFX); "Infinite Native Boost" targets the separate rocket-boost family; no vanilla nitrous toggle; its `VehicleMod` enum names slot 17 `Unknown17`.
- **Ecosystem hash-name conflict**: Menyoo binds `0x465EEA70AF251045` as `SET_NITROUS_IS_ACTIVE` (these notes call it `_SET_NITROUS_IS_VISIBLE`) — trust behaviour over the name.

## Two-projection route speed (future idea)

- Long-term: replace `followTrackSpd`'s geometric `√(g·grip·r)` with a two-projection system — a *true* ballistic projection (`ProjectAhead`, self-calibrating) and a *pessimistic* reduced-grip projection.
- Caveats the rebuild must solve:
  - a projection is a **limiter, not a planner** — it assumes current velocity+accel continue, so it cannot see future braking (the apex braking map stays);
  - multi-second ballistic horizons are physically wrong;
  - a target derived from a projection that depends on current speed risks a self-referential feedback loop (needs damping or latched verdicts).
- The pessimistic variant's value is anticipatory — ease speed *before* the edge, not the offshoot cap's after-the-fact emergency. Reference pattern: `ApplyOffshootBlend`.

## TRlat ladder

- The slide-response envelope is parameterized by `Handling.LateralTractionCurve` alone.
- The two **steering-limit rungs are RETIRED** (allowance base ×0.33, ceiling ×0.5) — replaced by the two-sided corner-geometry ceiling (AGENTS.md pipeline step 4). The formula is kept as history, not as a fallback: **restoring the rungs would *loosen* the limit, not tighten it** — Ackermann sits below them above the ~17 mph crossover.
- Still live: the two **slide-handling rungs** — `SlideBlendStartFraction` and `SlideBlendFullFraction`, both fractions of `Handling.LateralTractionCurve` — plus the `IsFullCountersteer()` pedal gate (`Racer.cs`). The fractions this note once quoted have moved since; read them there, not here.
- Do not confuse either with the removed MaxBrake rampdown threshold (`2 + TRlat × 0.2`) — a different use of the same fraction.
- **Corrected**: `_slideCountersteerDegrees` (once cited as the stored countersteer) **no longer exists** — the live value is the local `countersteerTarget`.
- The blend lerps the final steer toward "damped course steer − countersteer correction"; the correction itself is at **1 × slip**; lane steer is live again.
- **Measured band** (parsed from `Log.log` `TRlat for <car>` lines): ~10.75–12°, drift variants far above (`ISSI8` 21.75°, `DRIFTCHAV6` 28°) — "a slide" is a per-car quantity up to 2.5× apart. The `[1,100]` guard's fallback is 22 — re-check that log line after any handling swap, every ladder threshold doubles if the read falls out of band.

Related durable lesson (also in AGENTS.md): **corrections are corrections — never reuse one as an absolute target.** A value stored as "subtract from the PD" carries the *opposite* sign of the steer direction it wants; lerping toward it steers *into* the slide (this exact mistake inverted countersteer at full slide priority, caught in-game). Reconstruct the full target (trajectory terms + correction), not the correction alone.

## Steering limit (`ApplySteerLimits`)

- Two side limits, one clamp; it runs **last** in the pipeline.
- `SteerLimitRight` / `SteerLimitLeft` default to `min(vanilla, Ackermann)`.
- Vanilla's curve is `SteeringLock / (1 + k × v)` (the `−5` shift removed); Ackermann is `atan(wheelbase × grip × g / v²)` on a **bone-derived wheelbase** (`ARS.GetWheelBase`: both axle centres averaged, projected on forward, bounded 1–6 m, fallback 2.7). The pair crosses at ~17 mph; **Ackermann owns everything above**. It is the tightest corner the grip allows, and `SteerLimitedSpeed` inverts that same grip and gravity — retune one without the other and the speed plan and the steer cap desynchronise silently.
- **Countersteer is not exempt**: the side the wheel is on is *raised* (gated on the steer-vs-yaw sign test **and** the slide blend engaged) to `Math.Max(ceiling, min(|SlideAngle|, lock))` — a raise that can never lower a limit. This replaced a sign-test exemption that let the countersteer side run **unbounded**.
- **Two order constraints**: the limiter sits after every steering-request writer in `ProcessAI` (the stuck-recovery override writes `Control.SteerDegrees`, not `Control.SteerInput`, to stay inside it); `TranslateSteerToInput` converts the request afterwards — **a steering writer added below the limiter is a silent bypass**.
- The brake release lives in `ConvertSpeedToPedals` (runs first; its consumer, the post-slew `Min`, is there).
- **Grip source is `CurrentMechanicalGrip`, not `BaseMechanicalGrip`**: the base has the downforce term divided out, so it reads *low* on downforce cars and would tighten the cap for exactly the grippiest ones.
- **The declared grip ceiling is `CurrentMechanicalGrip` — never multiply grip by gravity and treat the result as G**, even though the engine somewhere does.
- **A removed system, named so it is not rebuilt blind**: an empirical peak-memory scheme once learned the steer angle that produced the best *measured* lateral G. It was built and deleted — its constants were the only survivors and had no readers left — so treat it as a decision already made rather than an open idea; recover the code from git if it is ever revisited.

## Side-by-side heading match (`ComputeSideBySideSteerCorrection`, `Racer.cs`)

- **The match is one-way**: it applies only while the overlapping rival is moving toward this car's side (the rival's *own* velocity against the separating axis). A rival drifting away is leaving room; this car's own closure stays the rival-walls' business.
- **The side convention, verified**: `+ = right` — `SignedLaneOffset` (`AutosportRacingSystem.cs:550`) and `RelativeOffset.X` / `LateralGap` (`DataStructures.cs:163`) are the same `Cross(dir, WorldUp)` dot; `Cross(forward, up)` really is world-right. `TryPickAvoidanceSide`'s `passLeft` names the side it *passes on*, not the rival's side.

## Lane steer — one flat P, deliberately no ceiling

- The lane term is a single proportional law on lane error, and it must stay **uncapped**. A ceiling flattens the top of the P, so most of a big lane move runs at a constant command that builds lateral velocity the short tail cannot shed — bang-then-taper, the exact overshoot it was added to cure. Driven both ways; uncapped won.
- Two levers: the gain (halved for the move to the outside — `LaneGainDegPerMeter` / `LaneSteerOutsidePercent`), and the low-speed ramp on the ceiling that lets the P's taper reach the tyres at lane-move speeds. The damped approach survives only because the yaw damper opposes the rotation the P just started.

## Steering damping (`SteerDamping`)

- **The gain is stored, not derived** (`a9603c4`): `SteerDamping` = `ARS.SteerDampingGain` verbatim, an absolute gain in **seconds** applied to `(yaw − target)` — the reference is the **aim point's** required yaw (`SteerDampingAimReference` `Racer.cs:960`, fed by `_steerAimCurvature` at `:714`; the zero reference and the old `SteerDampingTrackReference` switch are both gone). The **term still divides by `max(BaseMechanicalGrip, 1)`** (`Racer.cs:970`).
- **Corrected — the `grip` column of `pidump.txt` is NOT a damping input**: it is the **model** native `GET_VEHICLE_MODEL_MAX_TRACTION` read raw in `BuildPowerCache`, while live grip reads the **spawned-handle** native then `/= 1 + 0.035 × Handling.Downforce` (`UpdatePerceivedGrip`) — so on a winged car live grip is **lower** than the column. TRlat is a **slip angle in degrees**, not the TCS's quantity (see the wheel-memory bullet). Any grip span quoted from the column is **installation-dependent** — re-derive with the `arspidump` cheat. (The old damping rationale lives in `AGENTS-STEERING.md`'s ranked list.)
- **Why a per-car gain cannot be a static**: `ARS.SteerKD` used to hold the gain directly, and a grip-derived value there would have every racer overwrite the others' gain every tick (grip is per-car). **A per-racer value stays a racer property, never a static — read the property, not the static.**
- **Off-road gravity, not grip, is the flag's only effect** (still unmodelled, fix specified): it scales `BaseMechanicalGrip` by the gravity multiplier in `UpdatePerceivedGrip` — a permanent per-car property applied once in `Initialize` (`Racer.cs:392`), never a surface state — do not describe it as an off-road condition; that misreading has been made once already. It double-counts, verified in the leaked engine: the flag raises **only the wheel integrator's gravity** (`Vehicle.cpp:31323`, `m_fGravityForWheelIntegrator = fGravity × fGravityMult`) and leaves the traction coefficient alone — the native ARS reads is `m_fTractionCurveMax × fTractionMult`, downforce terms only (`commands_vehicle.cpp:6250`). Multipliers are `Vehicle.cpp:449-451`, chosen at `:31304-31311` — **mutually exclusive, the base bit winning** — with a hard-coded Mesa3 exception at `:31314`. ARS tests only bits `0x200000` and `0x800000`, so the base ×1.1 tier, the precedence and both special cases are unmodelled.
- **The setting key was renamed, not reused** — the third instance of that idiom. A stored value under old semantics trips the repair pass's "snap an in-list numeric to the nearest offer" rule and becomes a plausible, invisible wrong number (`SteerDampingScale` → `SteerDampingGain`, `a9603c4`). **Rule: when a setting's *meaning* changes, change its key too — a repaired value is worse than a reset one, because it is plausible and invisible.**
- **A menu list lookup must be formatted to match the list's own strings.** `GetFloat(...).ToString(InvariantCulture)` renders `1f` as `"1"`, not in a list of `"1.00"` — so `IndexOf` returns −1, `Math.Max(0, …)` snaps to the **first** item, and assigning `SelectedIndex` fires `ItemChanged`, which *writes* that first value — silently rewriting the setting to the first option on every load. Format with `"0.00"`. **Latent in any numeric list whose entries differ in string form from the default's `ToString()`.**
- **Wheel memory (`wheel+N` over `GetWheelPtrs`)**: the TCS read at `+0x174` is a per-wheel **slip RATIO**, dimensionless — 0 = free rolling, traction peaks at argument 1.0, flat from 2.5 (`sfTractionPeakAngle` / `sfTractionMinAngle`, leaked `wheel.cpp:94–97` — the "Angle" names are historical; the curve's true argument is the ratio, defined at `:8364–8365`). ikt32's MVT labels the same slot "overheat" — an unverified +8 guess, superseded here. `+0x198` = per-wheel surface grip multiplier, ~0 lifted (`MeanWheelGripMultiplier`); `steer+8` = per-wheel drive power (pattern-learned, `0x1D8` fallback). **Slip ratio ≠ slip angle in either direction** — `LateralTractionCurve` is an angle in degrees on the *lateral* curve, and a wheel's cornering slip angle never enters `MaxWheelSlip`. **The slip scale, settled: 0 free rolling, peaks at 1.0, flat from 2.5** (a stopped wheel reads ~15); an early commit title still says 0.4 — the old ÷2.5 transcription error (`m_fFwdSlipAngle` = raw × 2.5, `wheel.cpp:4497`/`:5220`) — take 1.0, not 0.4. Coefficients × `fMult × fLoss` at `:3194`. The engine's own cheat TC clamps at ±`MinAngleInv × LossInv` (`:4508-4511`) — a *slip-angle* limit in its own peak-hold, **not** the ratio scale the line above settles, so it is no benchmark for this threshold — and spin-direction reads negative (`:5233`), matching ARS's convention. **The TCS target is the menu's slip threshold, halved off-track, and nothing else** — the same on every surface and speed. Two modulations removed for simplicity: surface-grip scaling (`2db98fd`) and the launch taper (`a6fcf7d`), which is where a launch allowance would come back from.

## Pedal map (`ComputeCombinedInput`)

- One linear map for both pedals, **no feedforward**: `Clamp(speedError / divisor, ±1)`, the brake's divisor being the throttle's × `BrakeErrorMultiplier`. It replaced a `signsDisagree` shortcut that returned full brake for *any* deceleration above 10 mph — redundant, since a genuine direction swap's error saturates on its own.
- **What that shortcut was hiding is droop, and it is live again**: a P-only map holds a decel only at a standing error, so under sustained braking the car tracks the plan *above* it. If braking ever under-brakes in long zones, this is the cause, not the decel formula.
- **The fix belongs on the pedal side, not the plan**: apply the plan's own demand as feedforward — `EffectiveBrakeFactor(apexNode)` is already the brake fraction it budgets for — and let the error trim. **Do not restore `PedalTrackingOffsetMps`/`BrakeDemandScale`** (`b767c19`, `07d5e57`): that coupled the plan to the pedal map's gain.

## ShowCheckpoints — full marker details

Each corner renders **two primitives**:
- **Standing torus ring** — `(MarkerType)1` (SHVDN2 hides this as `Cylinder` but the prop renders as the classic torus; cast through `World.DrawMarker` rather than raw `Function.Call` to dodge texture-arg marshalling). Anchored **below** `TrackPoints[corner.Node]`, X/Y scale = `trackPoints[node].TrackHalfWidth * 2`, camera-facing.
- **Centered exit chevron** — `(MarkerType)20` (`ChevronUpx1` / `PROP_MK_RACE_CHEVRON_01`), anchored **directly above** `TrackPoints[corner.Node]`, lifted above ground (matching FiveM `client.lua:452`). Direction = `(nextApex - apex).Normalized`; rotation per FiveM `client.lua:466–491`; `faceCamera=false`.

**LOD**: a corner renders iff the node delta from the player is within a window with a small negative grace — negative so a ring does not pop the instant it is crossed, not an off-by-one (delta = node − playerNode, plain subtraction for point-to-point, modulo for circuits via `ARS.IsPointToPoint`). The player Racer is passed into `DrawCornerCheckpoints(Racer player, …)`; its live `CurrentTrackPoint.Node` gives the player node. Runs from `OnTick`, guarded by `playerRacer != null`. FiveM reference `racingsystem/client/client.lua:393–491`; ARS adapts this to corners-only via `ARS.Corners`.

## ShowEdgeChevrons — full marker spec

Small blue half-alpha chevrons (`(MarkerType)20`, scale 1, `faceCamera=false`, rotation `(89, 0, -90)`) on both track edges, pointing along the track, positioned exactly at the edge (`TrackPoint.Position ± cross(direction, up) × TrackHalfWidth`, +0.2 m lift). ## Pace selection — current state, and two lessons from the window→ranking switch

**Current**: selection is a **ranking** — `VehicleSelector.SelectClosestByPace` does one pool pass, sorts by `|pace − target|` and takes the closest N (shuffled for ties). The bracket, the widen loop (`Options.WidenBracketFill`), `PowerBracketScale` and `VehicleSelector.Select` (plus its never-called `CreateDuplicate`) are deleted; a stale `PaceBracket`/`WidenBracketFill` key is never read, because `LoadSettings` walks the `DebugToggles` **dictionary**, not the enum. `Pace Offset` is a fixed signed integer list; Relative resolves `playerPace + offset` **once per `InstanceGrid`** into a local, and must never be written back into `PowerTargetScale` — that write-back corrupts the persisted absolute target. Pace Mode alone decides the anchor for every grid; `ComputePlayerCarPaceIndex` is gone with the join override. The b845170-era wording is in git at `b845170` if ever needed.

**Lesson 1 — clamping an anchor is inert for a ranking.** Clamping into `[min,max]` cannot change a distance *ordering*: every candidate's pace lies inside the span by construction, so the sequence is identical. The fleet-span clamps were load-bearing only for a **fixed-width window**, so they were removed with it. The single surviving span use is a diagnostic log when the anchor sits outside the fleet.

**Lesson 2 — the switch inverted non-finite-pace handling.** A window *excluded* non-finite paces; `OrderBy` over a ranking sorts **NaN first**, so a NaN score would have been preferred — the opposite of before. Root cause: `BuildPaceIndex` filtered grip and mph but **not** `accel`. The computed score is now validated before entering `ModelPaceIndexCache`.

**Electric detection — a real bug found and fixed (`96f5a72`)**: this file used to record `GET_IS_VEHICLE_ELECTRIC` as `0xD839450756ED5A80`. That hash **is not a native at all** (not in SHVDN2's `Hash` enum, no member name contains "ELECTRIC"), and calling it returned non-zero for *every* model, so `ModelElectricCache` flagged all 488 cars as electric and the correction was silently applied **to the whole fleet**. The real native is `0x1FCB07FE230B6639`, model-hash based, build 3258+; verified in game: 19 electrics. **A native hash nobody has verified in game is a guess, and a wrong one fails silently and plausibly.** **Follow-up**: `96f5a72` repointed only the *selection* path — `Racer.Initialize` and the player-pace fallback kept calling the bad hash, so spawn-time pace over-applied the bonus while the grid was ranked on the corrected flag. `Racer` now reads `ModelElectricCache`, the fallback calls `ARS.IsElectricModel`; the bad hash appears nowhere in `src`.

## Settings folder — declared inventory + repair (`3fa7737`, `0fd4e0a`)

`src\SettingsRepair.cs` is the inventory: which ini files ARS expects, which keys each must hold, and what a healthy value looks like. Three passes run from `LoadSettings`, in an order that is load-bearing:

1. `CreateMissingFiles()` — first, before anything reads a store. Creates `Settings\` and moves `DevSettings.ini` to its legacy migration name when necessary.
2. `PruneOwnedFiles()` — still before any store reads its file, so no cached `ScriptSettings` object exists that could later `Save()` a pruned key back. Line-level filter: inside `[MENU]`, a `key = value` line survives only if the schema declares the key; every other line is preserved verbatim. Rewrite goes through a temp file + `File.Replace`.
3. `CompleteOwnedKeys(...)` — last, **after** the legacy migrations and the `LoadSettings` reads. Fills missing keys with declared defaults and normalises rejected values, through the `MenuSettings` API (`Get(key, null)` is a side-effect-free existence probe — `SeedIfMissing` returns early when the fallback is null).

**Ownership rule** — `Menu-*.ini` are the only active settings files and the schema owns them outright. `Settings.ini`, `Options.ini`, `DevSettings.ini`, `DevConfig.ini`, and `MemoryOffsets.ini` are retired: the remaining migratable values are copied into the menu stores, then all are deleted.

**Invariant: a created file holds exactly the values the code would use if the key were absent**, so creating one cannot change behaviour. That is why `Track` and `PaceTarget` are declared *optional* (no default): absence is meaningful for both (an absent `PaceTarget` triggers the fleet-span middle autoselect in `RefreshPowerControls`).

**Value policy**: `Bool` and plain numbers must parse (garbage → declared default); a number with a domain list (`TimeoutSeconds`, `AIRacerAutofix`) **snaps to the nearest offered value**; list-backed strings (`GridSorting`, `AiNitro`, `PaceMode`) must match a spelling exactly, a case-only difference is rewritten to canonical, anything else resets; `GridSize` is range-clamped. Optional keys are handled by the prune pass: a declared **numeric** key that does not hold a finite number has its line dropped. That rule exists because of a defect caught in-game (`0fd4e0a`): seed-on-read wrote the sentinel `PaceTarget = NaN`, defeating the "absent → middle of span" branch. **Gotcha: never hand a non-value sentinel (NaN) to a seeding getter as its fallback; probe with `MenuSettings.TryGetFloat` (non-seeding) when absence is meaningful.**

## Gs-aware preview steering (lane error blend)

**This design is LIVE again** — the authority chain containing it was restored from `1f4516d`. The notes describe what is actually executing, not history.
- Nose-aimed steering measures lane error at the car, but at speed centrifugal force (already measured by `ProjectAhead`) curves the real path, so it overshoots. The lane error in `ComputeSteering` is therefore blended (at the car) with the **0.5 s Gs-aware projection** (`LookAhead.HalfSec` + `ProjectAhead(0.5f)`, a hardcoded local half-and-half — no knob); the **1 s** slice is the off-track cap's read, not this one.
- **Lane steer conversion (proportional, `b333dc4`)**: lane error (metres) → steer angle by a **flat degrees-per-metre gain with no ceiling**, halved when heading to the outside of a tight curve — a two-value step, **not** a speed-scaled clamp. The old `atan2(laneError, lookahead)` is gone (its gain shrank exactly when speed rose or grip fell). A NaN guard sits before the clamp. `LaneGainExponent` is a dead field — declared, never read, in no ini.
- **Physical repulsion** (velocity-oriented box, separate from walls): inside it, react only to rivals **actually closing laterally** and **add** a steer-away term to the lane steer — never overwrite it (overwriting broke the lane steer: parallel traffic made the sign filter coin-flip and replaced the bias with ~0). Magnitude scales with closing speed × distance.
- The projection read is one frame stale by design (`RunTimedCore` runs before `ProcessTick` refreshes `AccelerationVector`) — same staleness all projection consumers accept.

## Corner outside approach — the release window

- **The release is a flat time before the entrance, not a width-scaled one.** `ComputeCornerTargetLane` gates the hold on `timeToEntrance`, and the window is `[OutsideReleaseSeconds, OutsideReleaseSeconds + 3 s]` — the outside phase is always 3 s long and retuning the release **shifts** the whole phase rather than lengthening it. `timeToEntrance = fwdToEntrance / max(speedMps, 1f)`, where `fwdToEntrance` is a **node count** (treated as metres, modulo-wrapped on circuits).
- **Driven: 0.5 s let go too late to help the apex; 1.05 s has the cars touching the apex better** (driver-verified), which is why the value moved.
- **The current-speed divisor makes it release early under braking, never late** — the car always has slightly *more* than the nominal time left (the safe direction); dividing by a predicted entrance speed is the fix if it ever reads short.
- **A separate hard kill at `fwdToEntrance <= 2` clears the latch**, so a released hold cannot re-engage mid-corner. It beats the time gate only at crawl speed, a backstop rather than the normal release.
- **`OutsideReleaseSeconds` is a `static float` with no writer** — effectively a constant, left mutable; not a menu item and not a save key.
- The entrance is the corner's own: `c.StartNode` when the track file supplies it, else `apexNode - c.LengthStart`. Returning `0f` means *no override* — the caller keeps the high-speed line's answer, and the car's own lane when that has none (`Racer.cs:413-417`).

## Steer-In Bias — the deliberate skew on the steer ceiling

- **The one knob that is knowingly not physics.** The ceiling is computed 1:1 (vanilla curve vs Ackermann, whichever is lower) and then **Steer-In Bias** adds a fixed number of degrees, floored at half the geometry and clamped to the car's lock (`Racer.cs`, `ApplySteerLimits`).
- **It is additive, not multiplicative, and that choice is the whole design**: a multiplier's absolute effect is largest at low speed and negligible at speed — the opposite of what "steer in" needs; an additive bias applies the same degrees everywhere, so it is proportionally largest exactly where the ceiling is smallest (at speed). Driven and kept in the positive direction; the negative half saturates against the floor above ~70 mph.
- **The floor is not optional**: `geometry + bias` can go negative at speed (which would invert the clamp), and even exactly zero is a car that physically cannot steer — so the result is held at **half the geometry**.
- **Wiring is the `SteerDampingScale` pattern, four places**: the static in `AutosportRacingSystem.cs` assigned in the item's own `ItemChanged` (a `Racer`-read static must be, or the save only lands on restart), `SaveRacerSetting` into `Menu-Settings.ini`, the `LoadSettings` read, and the `SettingsRepair` `KeySpec`. A numeric key **snaps an out-of-range stored value to the nearest offer**, so a hand-edited value cannot survive a load.
- **The range is deliberately not recorded here** — it is a tuned value; the options array and the `KeySpec` are the source of truth.

## Logging — levels, and why `None` is the default

- `LogImportance` is a **floor**, not a switch: `Log()` returns when `LogLevel > i`. `None` is deliberately the **last (highest) enum member**, so it silences every level through that same test with no second branch — and it is the **shipped default** (code static *and* `SettingsRepair` KeySpec). Levels persist by **name**, so adding a member renumbers nothing.
- **The session banner** (truncate + separator) is written in the ctor **before `LoadSettings`**, so it cannot consult the stored level — 2 writes a session; it also stops a stale log reading as current evidence.
- **`forced: true` calls** — all error paths: settings repair, model and ped load failures, the `OnTick` catch, the bridge probe. Keeping those is the whole reason `None` is a floor rather than a hard kill — `VerifyScriptBridge` runs *before* `LoadSettings`, so a suppressed forced line would make a bad SHVDN asi/dll pairing completely silent in our log. That is why the release README's "the log names the reason" stays true under the default.
- Verified in game: with `None` the live `Log.log` is exactly the two banner lines plus the single forced `Initialization complete.` line.

## Crash triage — Rockstar writes the dump, and this install has a recurring crash

**Rockstar's own handler captures a game crash, so there is a record even when Windows reports nothing.** A crash writes a minidump plus a context file to `%LOCALAPPDATA%\Rockstar Games\GTAV\CrashLogs\`:

- `<guid>.dmp` — a **user minidump**. Its structures are readable without a debugger: the **exception stream** gives the exception code, faulting address, faulting thread id and — for an access violation — `ExceptionInformation[0]` = read(0)/write(1)/execute(8) and `[1]` = the address touched; the **module list** resolves that address to module+offset; each thread's **stack range** is in the file, so scanning it for pointers into module ranges gives a crude backtrace. The Windows Application log stays **silent** for these (no `Application Error`, no WER, no `%LOCALAPPDATA%\CrashDumps` entry) — a missing WER event is not evidence that nothing crashed.
- `crashcontext.log` — the **last** crash only (overwritten), with game state at the crash. Useful for "what was the session doing", useless for older crashes.

**A real unwind needs a debugger, and the CLI is one install away**: `winget install Microsoft.WinDbg` registers `cdbX64.exe` (classic engine, runs headless) in `%LOCALAPPDATA%\Microsoft\WindowsApps` — where to look when it is installed but not on `PATH`. `cdbX64.exe -z <dump> -y "" -c ".ecxr; k; !analyze -v; q"` gives the faulting instruction with operands, the properly unwound stack, and the `AV.Type` / `WRITE_ADDRESS` / `FAILURE_BUCKET_ID` verdicts. `GTA5.exe` has no public symbols, so a game offset **cannot be resolved to a function name** — module+offset and the call chain's offsets are the fingerprint; the bucket reads `INVALID_POINTER_WRITE_c0000005_GTA5.exe!Unknown` for game-side null writes.

**This install's recurring crash (three occurrences, one signature).** `GTA5+0x652263`, `mov byte ptr [rdx+rcx+10h],al` with `rcx = rdx = 0` — a **one-byte write to address 0x10, i.e. into a null object's field** — from a thread rooted at `kernel32!BaseThreadInitThunk`. The unwind is **18 frames, every one `GTA5`** (no mod module, not JIT-managed code), byte-identical across all three: `0x652263 → 0x63c7e3 → 0x638fab → 0x6416cc → 0x168e909 → 0x16946c4 → 0x169b630 → 0x169b7be → 0x16a2de5 → 0x8157dc → 0x1687bad → 0x168739f → 0x28574 → 0x21c4b → 0x1686fa8 → 0x13cc → 0x1344e07 → 0x187f5d0`. Only the ASLR slide differs. Sessions: **08-15, 09-04 and 09-19**, all with `ARS.dll`, `LemonUI.SHVDN2.dll`, `NativeUI.DLL`, `TrainerV.asi`, `RTHandlingEditor.asi` and `HandlingReplacement.asi` loaded (the newest session additionally carried `HandlingIsolation.dll`, `HandlingIsolationDemo.dll`, `ModManager.*` and `NewChaseCam.dll`, so those are not its cause either).

**What that fingerprint does and does not settle.** It **exonerates any change made after 09-04** — the same crash predates it by five weeks: compare the faulting instruction *and* the call chain against older dumps rather than reasoning about coincidence. It does **not** exonerate the mods present in all three sessions, ARS included: a deterministic null write in game code is the usual shape of the game reacting to an entity a script deleted or invalidated (the `*Delete()` / teardown / script-reload lifecycle) — if it needs chasing, the repro candidates are a **scripts reload mid-race** and the **race-end entity cleanup**, not the raw memory writes. Other crash modes in the same folder: `0xE0434352` (a CLR exception faulting in `KERNELBASE.dll`, four occurrences) and `0x80000003` (int3 breakpoints, five in one 09-12 session — hooking/debug tooling, not a game fault).

**Possible misleading load failure — an external USB hard disk (observed once, not reproduced).** With a plain external HDD connected, GTA5 launched straight into a fatal `ERR_GFX_D3D_SWAPCHAIN_ALLOC_2` dialog and stopped responding; disconnecting the disk made the game load. WER already held earlier `AppHang_GTA5.exe` (`AppHangB1`) entries, so the condition is neither new nor ours — but the disk stays a **possible** cause, not a rule, until reconnecting brings the failure back. The trap is the error's name: it points at the DXGI swapchain and steers diagnosis to D3D/DXVK/display, while the hang it reports is a stalled main thread — the shape a slow or failing disk produces while the game enumerates drives at startup.

**Clearing the C# mods for a pre-script load failure is cheap and decisive.** On the failing launches `ScriptHookVDotNet.log` stayed stale while `ScriptHookV.log` and `asiloader.log` were rewritten, so the .NET script domain never started and no SHVDN script ran — ARS included. Establish the load order before reasoning about whether a recent change caused it.

## Vehicle memory layer — one implementation, memoized scans

- **`VehicleMemory.cs` owns every offset and every pattern scan.** The four control-struct setters, the handling-struct readers and the shared AOB scanner all live there, and `Racer` calls nothing else. `ARS.SetThrottle` was the only write path in the codebase with **no `CanWeUse` guard**, dereferencing `handle.MemoryAddress` unchecked — the exact shape of the `NullReferenceException` a ScriptHookVDotNet maintainer reported against the tracker's issue #8 after a game update moved the pattern.
- **The scanner is memoized, and that is the load-bearing part.** `FindPattern` caches per `pattern|mask` in a static dictionary (sound because the module base cannot move inside a game process). Before, an **unmatched** pattern bought a full module walk *on every call*, and every caller is per-tick and per-car — on a build where the pattern moved, that would have presented as a **frozen game** rather than "the brakes don't work". The cache reduces a miss to a dictionary lookup, so the failure mode is degradation instead of a hang.
- **Two misses report once, and forced** (`LogImportance.Error` with `forced: true`, so Log Level `None` cannot hide them): the control pattern (*"ARS cannot drive the cars"*) and the handling pattern (*"grip, steering lock, downforce and handling flags all read as zero"*), both naming `Game.Version`. Every other pattern miss stays at `Info` on purpose — the wheel-power pattern has a documented `0x1D8` fallback.

## Randomness helpers — the exclusive max, and what it silently costs

- **`ARS.GetRandomInt` is `Random.Next`, so its `max` is EXCLUSIVE.** An *index* bound written `Length - 1` loses the last element for good — that is how Steel Gray in `_randomColors`, the last matching Menyoo tuning file and the last `StreetRacerModels` ped were unreachable, while index bounds written as the length itself, and every *jitter range* (`(10, 50)`, `(0, 500)`), are correct as they stand. The helper now says so where it is declared — check that, not the call sites, before "fixing" a `-1`.
- **The sweep above missed five more sites, all in `SmartTuner`** (`9517976`): the style pick, the chosen group's livery options, `veh.SetMod(slot, random(0, count))`, the palette pick and the matte pick each passed `Count - 1`. They now pass the length — when this trap is next suspected, grep **every** `random(0,` call site rather than trusting the list here.
- **The shuffle idiom is `random(0, i + 1)`**: `Tips.cs` and `GridBuilder.cs` have it right, and `VehicleSelector.Shuffle` was a character short — passing `i` gives Sattolo's algorithm (uniform over *cycles*), so a shuffled list could never keep its own order and a two-item list always reversed. **One off-by-one of this family is deliberately left in place**: the tip roll is `GetRandomInt(1, Denominator)` — a rate, not an index, so fixing it is a tuning decision rather than a bug fix (the `9517976` audit changed it to `Denominator + 1` and the change was reverted).

## Cross-session hindsight notes

- **`TrackLoader` sets `Thread.CurrentThread.CurrentCulture = en-US` and never restores it**, so every later `ToString`/`TryParse` on the game thread is silently reformatted — and the track files already carry several incompatible culture conventions. Same family: `TrackFile`'s `int.TryParse(float.ToString())` truncates fractional widths and writes 0 with no else branch.
- **Crest handling has a sign and a home.** `CrestGs` negative = crest / positive = dip; the crest multiplier belongs on the grip-limited decel base, not the grade term, and a positive value must be discarded before the floor. The behind-guard is the **extent test**, not the sign of `toCrest` (`CrestDecelFactor` `Racer.cs:3194` bails when the whole ramp is behind the car) — a car still inside the crest's extent keeps the portion ahead of it, which a bare `toCrest < 0` guard would wrongly drop. The earlier note calling this a point-to-point bug is retired.
- **The brake learner's full-pedal threshold sits above the downshift gate, so its own target pushes the car into engine braking it cannot see.** Separately, `Corner.SecondsToEntrance` is declared and never assigned (dead field); the real value is computed locally in `ComputeCornerTargetLane`.

## Sideloaded fleet handling

- **The grid's cars are custom and their handling is sideloaded, not in the game's own meta**: `VSLooseStream.asi` mounts loose FiveM-style resources from `Sideload\`, each declaring `data_file 'HANDLING_FILE'`. **ARS reads the live `CHandlingData` from memory, never these files** (`VehicleMemory.cs`), and it reads the per-racer handling values once per racer at racer init, so a mid-session edit moves the car without moving those reads.
- **`Sideload\0_vsl-handling\handling.meta` is the file of record and the only declaration of these names** — the per-car copies were emptied to stubs, their contents kept beside them as `*.bak-vslpriority` and **never to be restored**: while those duplicates existed, boot could serve a stale generation of the shared file. It is a **hand-balancing** surface, judged by driving rather than by ARS — tuned at LSIA, settled at NURBGP. **Its `<strHandlingFlags>` is a numeric hex string parsed straight into `hFlags`** (`handlingMgr.cpp:1699`), and nearly every car sets `TYRES_CAN_CLIP`, which *raises* the wheel's compression cap so the tyre sinks into the ground when bottoming out (`wheel.cpp:1359–1367`) — so a car that looks sunk or clips is a per-model flag, never a player-vs-AI difference (`AGENTS-VANILLA-STEERING.md`).

## Grid car selection (pace-matched)

- **Model stat natives need an int hash, not a spawned handle** — that is what makes pre-race evaluation free, with no car in existence. The spawned-handle natives are *different functions*, so don't mix them up; the hash table is in this file.
- **The roster is one flat hand-editable file** — `Scripts\AutosportRacingSystem\Vehicles\cars.txt`, one model key per line, `#` comments ignored (`VehicleCatalog.cs:17`). `BuildPowerCache` (`AutosportRacingSystem.cs:447`) hashes each line and **rewrites the pool in place to canonical hash-string keys**, which every consumer is keyed by; the `arsbuild*` cheats only *append* and refresh the roster live.
- **Threading contract**: the load thread only *discovers* the pool by pure file I/O, while `BuildPowerCache` reads the natives on the **main thread**. **Calling GTA natives on the background thread hard-crashes the game.**
- **Pace score (`AutosportRacingSystem.cs:93`) is a raw per-model number, not 0–1**, and the leaderboard prefix is the same metric the grid ranks by. Electric models are scored at the **peak** of the game's own drive-force ramp — `f3fc274` replaced the driver-verified ×2.95 midpoint — with the flag from a verified native.
- **Selection (`VehicleSelector.cs:12`) is a ranking, not a window** — one pool pass ranks every paced model by distance from the target, takes the closest N with a shuffled tie-break, and returns model keys without touching a file. `SelectHardcoded` (`VehicleSelector.cs:42`) is the full-roster test bypass.
- **Force-Fill Grid (Settings → General Settings, `ForceFillGrid`) recycles the models that actually spawned, round-robin, until the grid target is met** (`AutosportRacingSystem.cs:3651`) — a one-car pool like `tests.txt` fields a full grid of it, and a model that spawned nobody is never retried, so a broken roster line costs its load wait once.
- **Grid slots are built to order and the count must include the player.** `BuildGridSlots` (`TrackLoader.cs:588`) runs again for `Racers.Count` right before `GridBuilder.Place` (`GridBuilder.cs:17`) because `Place` reads **two slots past each car**, and `AddPlayerToGrid` (`AutosportRacingSystem.cs:1920`) adds the player *after* the grid was sized — `470a1a1` shipped exactly that crash.
- **Pace Mode is the sole authority on the anchor (`759a36a`)**: Relative resolves from the player's pace, Absolute from the persisted target, and **every** start path resolves from the mode with no override of its own. `PowerTargetScale` has exactly two writers — its own menu item and `RefreshPowerControls` (`AutosportRacingSystem.cs:1236`).
- **Menu vocabulary**: the items are `Grid PI Mode` / `PI Offset` / `PI Target` while keys and code keep the name pace. **`PaceTarget` is a seed, not a preference** — `RefreshPowerControls` clamps it to the live fleet span on every menu build and saves the result, so do not reconcile a live-vs-Dist difference in it.

## Dependencies and UI

- **Two folder constants drive every path**: `ARS.ScriptsFolder` (`scripts\AutosportRacingSystem`) and `ARS.SettingsFolder` (its `Settings\`). The `.csproj` `GtaArsScriptsDir` mirrors the first independently — keep them in sync.
- **Per-menu ini persistence (`9783143`)**: one file per menu group in `Settings\`, named after the menu — `Menu-Race.ini`, `Menu-Settings.ini`, `Menu-Debug.ini`. A renamed file migrates key-by-key then is deleted; the key list comes from `SettingsRepair`'s schema, never a copy of it.
- **`MenuSettings` (`MenuSettings.cs:8`)** is the store: one lazy `ScriptSettings` per file, `Set` saves on change, a getter on a missing key seeds the fallback back, `Migrate` (`MenuSettings.cs:81`) carries a legacy value only when the key is absent. **Lists store values, never indexes.**
- **A setting read as a static must be assigned in its own `ItemChanged`** — saving alone only applies after a restart. Live readers like autofix/timeout need only the save.
- **Settings repair (`SettingsRepair.cs:17`)**: `LoadSettings` (`AutosportRacingSystem.cs:2887`) runs `CreateMissingFiles` → `PruneOwnedFiles` before any store read, then `CompleteOwnedKeys` so defaults cannot shadow migrations; legacy standalone files are removed last. This path still needs in-game verification.
- **The one thing the repair passes cannot enforce is the code agreeing with the schema**, and that gap is what cost the governor switch a silent revert: a key the menu writes but the schema omits is pruned on the next load, and a key the menu only *reads* is worse — the store seeds it into the file so it appears to persist. **Two mechanisms now close it.** The store asks `SettingsRepair.IsDeclared` before touching any key — an undeclared read or write is refused and reported once per file and key at forced Error (`MenuSettings.cs`) — and `docs\check-settings-keys.py` catches the static half: the `FileSpec` blocks against every `Set`/`Migrate`/`SaveRacerSetting`/`Get*` use, the `OptionsFor` calls against keys that have a domain, and the schema's own defaults against its own repair, exiting 1 on any error. **Its coverage is literal-only and its summary says so** — loop-declared keys (the Debug toggle table), computed defaults and computed domains are counted as uncheckable rather than silently assumed.
- **Menu option lists come from their enum (`9b8da25`)**: `EnumLabel` (`AutosportRacingSystem.cs:2999`) spaces a member's name out, the item index *is* the enum value, and the store keeps the enum **name** — so only renaming a *member* needs a migration. `SettingsRepair`'s domains are `Enum.GetNames`, so they cannot drift from the menu.
- **`sillynames.txt`** lives in `ScriptsFolder` (ship copy in Dist), reshuffled per `LoadGrid` (`AutosportRacingSystem.cs:3283`); AI racers pop names without replacement and the player keeps `Game.Player.Name`.
- **`Dist\AutosportRacingSystem`** is the version-controlled ship mirror; `RefreshDist` robocopies **game → Dist** and `Dist/**/*.dll` is ignored. **It ships `Settings\` EMPTY** (an inert `.gitkeep` keeps the folder in git *and* the zip) and the mod fills it on first run — `RefreshDist` excludes the source `Settings` outright, or the developer's session values would *become* the shipped defaults. **`Tracks\` has no such exclusion, and with the creator live any track the user makes is re-dropped into Dist on the next build** — a dirty tree after using the creator is expected, not a mistake; shipping one is a deliberate stage (the user's call: no ignore rule).
- **SHVDN `ScriptSettings` quirk**: `Load` never returns `null` (a fresh empty object), and `Save` creates the file via `File.CreateText`, so a deleted file regenerates on the next write. Booleans are `True`/`False`, parsed case-insensitively.
- **LemonUI SHVDN2** replaces the hand-drawn menu; every menu is built in `InitializeMenu` (`AutosportRacingSystem.cs:618`). Three invariants: **only a 10-row window is drawn** (`NativeMenu.maxItems`, never overridden) so an item added at runtime lands below the fold and reads as "it didn't work"; **assigning `SelectedIndex` fires `ItemChanged`** so a handler must not touch items that don't exist yet (`9b8da25`); and the root/Race/Settings/Other/Creator inventory is fixed, with the two spawn items six slots apart and hidden while Staged Spawns is off.
- **LemonUI ships with the release** (`libs\LemonUI.SHVDN2.dll`, MIT, author's permission; 1.5.2 is the last v2-API release) and is staged **by name** in `deploy.yml`. The API dll is deliberately the opposite case, so never replace that line with a `bin\Release\*` wildcard (`AGENTS-SHVDN.md`).

## Durable gotchas — code, helpers, rendering, settings

**Trigger**: inverted gate, De Morgan, negated filter, early continue, Remap, NaN, dead null-check, OnTick pause, positional Options enum, `DrawMarker` budget, marker rotation and pitch, prop `RightVector`, streaming ptfx.

- **`if (1 == 2) return;` is an INVERTED gate — it disables nothing**, because the return only fires when the condition is true and it never is. Correct idioms are a bare `return;` or the block form; this bit the start-line flare disable (`bdd1b29`) for weeks.
- **Remap with a descending output range + `clamp=true` is inverted** by `Clamp` when `min > max`, and NaN compares less-than-anything. Keep output clamps ascending and use a descending *input* range for a reversed map.
- **NaN discipline**: `Clamp(NaN, -limit, +limit)` returns the min bound, i.e. instant full-lock — guard steering outputs and any clamp input that can be non-finite. Never hand a non-value sentinel to a *seeding* getter either, or it writes the sentinel into the ini.
- **An early-continue guard is the accept filter negated, so De Morgan inverts its NaN case**: `!(A && B)` is `!A || !B`, and a NaN makes every comparison false — the filter `Distance <= 30f && Gap < 0f` drops a NaN rival, while its rewritten guard `Distance > 30f || Gap >= 0f` does not fire and passes it. Rewriting a `Where` into a loop keeps the positive accept form (`bool closes = ...; if (!closes) continue;`) (`Racer.cs` card scans, `601313c`).
- **A null-check on a freshly `new`-ed object is dead code.** Two "cannot find file" popups lived behind `if (new XmlDocument() == null)` while the real failures *throw*, so those paths have **no** error handling.
- Synchronous setup work can pause `OnTick` and temporarily suppress per-frame debug visuals; make it incremental if that matters.
- **`Options` enum values are positional**, so retiring a member renumbers the rest and one must never be persisted or exchanged as an int. Nothing does today, but re-check before any numeric consumer appears.
- **`World.DrawMarker` has a per-frame render budget**: markers past it are **silently not drawn** and draw order decides who loses, so long debug geometry belongs in `DRAW_LINE` instead. The budget is shared with every other marker the script draws that frame, so a visual can break because something *else* got greedy.
- **A marker's rotation vector collapses at a 90° middle slot**: with the middle component at 90 — the value that lies a chevron flat — the first slot yaws and the last two roll in opposite senses, so **no single slot can pitch it**, however many are tried. Pitch a marker by tilting the `direction` vector it faces along and leave the rotation at the flat pointing configuration (the input trail's chevrons, `6111f6c`).
- **Two traps the flare rebuild exposed, both reusable**: a prop's own `RightVector` is perpendicular to *that prop's* forward, so an offset applied after its heading is turned 90° comes out parallel to the track — offset from the source direction instead; and a **named ptfx asset streams between frames**, so requesting it in a same-frame loop can never succeed — queue the entity and attach it from a tick (`TrackLoader.TickQueuedFlares`), logging a failed start rather than swallowing it.
